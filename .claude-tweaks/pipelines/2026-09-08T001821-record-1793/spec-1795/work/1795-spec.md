# 1795: dev-url-detection: lease-first probe, lease-based MATCH/FOREIGN, ephemeral start on the leased block

Surface: backend

## Overview

Makes the pipeline's own browser work use the same block the human's terminal uses. `_shared/dev-url-detection.md` gains a Step 0.5 that probes `http://localhost:{PORT}` from this checkout's lease first; Step 2.7's worktree check becomes lease-based (a responding port is MATCH iff it is in this checkout's lease), demoting the POSIX-only `lsof` heuristic to the no-lease fallback; "Ephemeral server start" uses the leased block and passes the managed env through instead of probing upward; wrap-up Section D stops the server by PID and no longer needs `lsof` when a lease exists.

**Complexity:** Low
**Estimated tasks:** 4

## Deliverables

- [ ] Step 0.5 "Lease-first probe": run `node "${CLAUDE_PLUGIN_ROOT}/bin/ports.js" env` in the checkout; when no lease exists for this checkout, the command prints nothing and exits 0 (#1791's own contract for that case) — treat that as "no lease," fall through to Step 1. Otherwise parse every printed `KEY=value` line into `LEASE_PORTS` (the full set of port *values* across all lines — `PORT`, and every `{NAME}_PORT`, not just `PORT`); HTTP-probe `http://localhost:{PORT}` (the value from the `PORT` line specifically) with the Step 1 check; on 2xx/3xx set `APP_URL` and skip Steps 1-2.7 (the lease *is* the worktree-awareness proof); on no response continue to Step 1 with `LEASE_PORTS` (the full set already parsed) remembered.
- [ ] Step 2.7 rewritten: when `LEASE_PORTS` is set, MATCH iff the responding port ∈ `LEASE_PORTS`, else FOREIGN — no `lsof`; when no lease, the existing `lsof` block stays, now explicitly labelled POSIX-only with the Windows outcome stated (PID unresolvable → FOREIGN, i.e. start an ephemeral server) — this is an accepted, stated trade-off: on Windows, an unleased project never reuses an already-running dev server and always starts a fresh ephemeral one, unlike POSIX where `lsof` can still find a same-cwd match.
- [ ] "Ephemeral server start" step 1 replaced: with a lease, re-run `node "${CLAUDE_PLUGIN_ROOT}/bin/ports.js" env` at start time (not the value cached from Step 0.5, to avoid acting on a stale snapshot) for `PORT` and pass every printed `KEY=value` line into the spawned server's environment verbatim — no allowlist beyond "whatever this checkout's own managed region currently contains" — so sibling services resolve to their own block; without a lease, keep the probe-upward rule. `ephemeral-server.txt` gains no new fields.
- [ ] Step 0's persisted-URL acceptance updated to the same lease-first rule: a persisted `stories/servers.yml` URL is accepted only when its port is a member of this checkout's `LEASE_PORTS` (or, with no lease, passes the existing worktree-awareness check); on mismatch, discard the persisted URL and fall through to Step 1's fresh probe rather than trusting it. Cleanup's standalone kill updated the same way (`kill {pid}` from `ephemeral-server.txt`; `lsof` fallback only when no lease) — cleanup always trusts the PID captured in `ephemeral-server.txt` at start time and never re-reads the live lease, so a lease that has since changed or expired cannot desync the kill.
- [ ] wrap-up Section D: `lsof` fallback wording qualified as no-lease/POSIX-only; with a lease the port is known and the PID kill is sufficient.
- [ ] `tests/dev-url-detection-lease-conformance.test.js` (new prose test) proving each assertion can go red per `skill-prose-conformance-tests`.

## Gotchas

- `cleanup-procedures-execution.md` is also edited by Unit 3 (Section C) — this unit is Blocked by Unit 3; rebase before editing.
- Keep `stories/servers.yml` semantics: a persisted URL is still subject to the lease MATCH rule, never trusted on its own.
- The `worktree-detect.js` `repoInfo()` check stays as the linked-worktree detector; only the PID→cwd comparison is replaced.
- The procedure's "Permissions required" note (writes in Step 4) is unchanged.
- This unit's interface with `bin/ports.js env` is pinned by #1791 AC12 (leased path: managed lines only; no lease: prints nothing, exits 0) — that contract, not this record, is authoritative if the two ever disagree; this unit is Blocked by #1791 (and #1792, #1793) precisely because it consumes that CLI and `port-services` without building either.
- Lease membership is accepted as sufficient proof of MATCH with no PID-level cross-check, unlike the retained `lsof` no-lease path — this is a deliberate trade-off, not an oversight: a lease can theoretically go stale between a process dying and Unit 1's gc or Unit 3's reap clearing it, but that window is no wider than the gaps `lsof`'s own PID→cwd comparison already has, and the lease-first path is what makes worktree-awareness work at all on Windows.

## Decision Rationale

See #1791 Decision Rationale — in short: a machine-wide lease registry (chosen over a path-hash or OS-assigned-port-0 scheme) hands each checkout a verified-free 10-port block; this unit makes the pipeline's own browser tooling prefer that same block over guessing, so a human's terminal and the pipeline's ephemeral server never disagree about which backend a frontend is proxying to.
