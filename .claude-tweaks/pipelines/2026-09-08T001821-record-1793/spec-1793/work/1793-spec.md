# 1793: ports: statusline segment and lease release at every worktree-removal site

Surface: backend

**Related:** #1235

## Overview

Makes each terminal show its own ports and stops leases from outliving their worktrees. A statusline segment renders the block base for the current cwd; both worktree reapers and the two skill-driven removal sites release the lease after a successful `git worktree remove`. Release failure is logged, never fatal — Unit 1's gc is the backstop.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- SessionStart/ensure (Unit 2)
- `/init`
- dev-url-detection
- Changing any reaper eligibility predicate (release runs only after a removal the existing predicate already approved)

## Deliverables

- [ ] `renderPorts(cwd, {home})` in `claude-tweaks-statusline.js`: reads the registry degrade-open, finds the lease whose `path` equals the realpath of the git toplevel of `cwd` (walk up to the nearest `.git` file/dir rather than spawning git — the statusline must stay spawn-free beyond what it already does; for a linked worktree the nearest `.git` is a *file* pointing at the real gitdir, not a directory — the toplevel is still the directory containing that `.git` file, not a path derived from the gitdir it points to, and the result must be realpath'd with the exact same normalization Unit 1's `registry.allocate`/`registryPath` uses for `path` — same casing, same symlink resolution — or a leased worktree's segment silently never matches), renders `:{base}` (e.g. `:20010`), `''` when none; inserted after `renderGit`. The registry read (including a present-but-malformed/throwing `readRegistry`, not just a missing `ports` module) is wrapped in one try/catch that degrades to `''` — AC1's "unreadable registry ⇒ byte-identical output" covers both the missing-module and the bad-data case, not just the require.
- [ ] `release(real, {home})` — imported from Unit 1's `plugin/bin/lib/ports/registry.js` (#1791) — call in both reapers immediately after a successful `worktree remove` (rm exit 0), wrapped so a throw is recorded in the result as `portsRelease: 'failed: {msg}'` and never changes the reap outcome. `release` on a path with no lease (not every worktree acquires one — Unit 2/`ensure` is out of scope here) is a no-op that reports nothing, matching #1791 AC6's release contract — this is the common case, not the exceptional one. Use one consistent identifier for the seam across the Deliverable and Technical Approach — the injectable option key is `releasePorts`, defaulting to `release` from `registry.js`; a test's injected spy binds to `releasePorts`, never to a separately-named `release`.
- [ ] `plugin/skills/tidy/scan-procedures.md` + `plugin/skills/tidy/SKILL.md`: one added line each after the `worktree remove` instruction: `node "${CLAUDE_PLUGIN_ROOT}/bin/ports.js" release --path {path}` (best-effort: on failure, print to stderr only — never blocks the finding, and no other visibility surface exists for the skill-side call, unlike the reaper's structured `portsRelease` field).
- [ ] `plugin/skills/wrap-up/cleanup-procedures-execution.md` Section C: the same release line as the step after removal, always with an explicit `--path {path}` flag rather than relying on the CLI's cwd-based default — `release(path)` only needs the path string, not a live process cwd, but the CLI's automatic `--path` default (`git rev-parse --show-toplevel` of cwd) stops resolving once the worktree directory is gone or the session has `cd`'d out of it. Passing `--path` explicitly removes the ordering dependency: for the own-cwd path, release the captured worktree path either just before or just after `ExitWorktree` — the explicit flag makes both orders equally correct.
- [ ] Tests for each of the above.

## Technical Approach

Statusline reads `registry.readRegistry({home})` from Unit 1 (require the module lazily inside `renderPorts` so a missing module — older wrapper install — degrades to `''`). Reapers import `release` from `plugin/bin/lib/ports/registry.js` with an injectable seam `{ releasePorts = release }` in their options object, mirroring how `runGit` is injected today.
