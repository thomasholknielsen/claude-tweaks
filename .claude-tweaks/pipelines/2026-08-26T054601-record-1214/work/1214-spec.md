# 1214: archiveRunDir: partial-failure revert coverage gaps beyond the #652 commit-failure path

Surface: infra

## Current State

- `bin/lib/reconcile/archive-merged.js`'s `archiveRunDir` moves every `work/` subtree via a batch of `git mv` calls (top-level + one per `spec-{N}/` in a multi-spec parent run dir), then issues one `git commit` covering the whole batch.
- #652 fixed the specific case where every `git mv` in the batch succeeds but the subsequent `git commit` fails: `revertWorkMoves` now reverts each moved pair (`git reset` then `fs.renameSync`, gated on the reset actually succeeding) so a commit failure never leaves the tracked tree dirty indefinitely.
- Two adjacent gaps were identified during #652's review (converged across independent review lenses) but are out of that record's stated scope (which is specifically "a git commit failure after mv succeeds"):
  1. **`git-mv-failed` sibling path has no revert for already-succeeded pairs in the same batch.** In the `for (const [src, dest] of workMoves) { const mv = runGit(['mv', src, dest], root); if (mv.failure) return { ok: false, reason: 'git-mv-failed' }; ... }` loop, if the *second* (or later) `git mv` in a multi-pair batch fails, the pairs that already succeeded *before* it are left moved-and-staged with no revert — the same "partial-failure leaves the tree dirty" defect class #652 fixed for the commit step, unaddressed here. Reachable whenever a run dir has 2+ `work/` subtrees (a multi-spec parent run with `spec-{N}/` children).
  2. **No test coverage for a multi-pair (multi-spec) commit-failure/revert.** #652's new tests (`tests/bin-lib/reconcile/archive-merged.test.js`) only exercise a single top-level `work/` pair for the commit-failure and reset-failure paths; a multi-spec parent run dir with 2+ `spec-{N}/work/` subtrees, where the commit fails after several `git mv`s already landed, has no regression coverage.

## Deliverables

- Extend the `git-mv-failed` branch (or introduce an equivalent helper) so a mid-batch `git mv` failure reverts every pair that already succeeded earlier in the same batch, leaving the tree in the same state it started in — mirroring the commit-failure revert #652 already built.
- Add multi-pair (2+ `spec-{N}/work/` subtrees) test coverage for both the commit-failure/revert path and the mid-batch `git-mv-failed` path.

## Acceptance Criteria

- [ ] A `git mv` failure partway through a multi-pair batch reverts every pair moved earlier in that same batch (no tracked entries left staged-but-uncommitted for the succeeded pairs).
- [ ] A commit failure on a multi-pair (multi-spec) batch reverts every pair, verified by a test using 2+ `spec-{N}/work/` subtrees.
- [ ] `npm test` passes in full.

## Technical Approach

In `archiveRunDir`'s `workMoves` loop (`bin/lib/reconcile/archive-merged.js`), the `git-mv-failed` return currently fires with no revert of pairs already moved earlier in the same iteration. Track which pairs have already succeeded (the loop already builds this set — it's the prefix of `workMoves` processed before the failing index) and, on a `git mv` failure, call the existing `revertWorkMoves(root, succeededPairs)` on exactly that prefix before returning — reuse the same helper the commit-failure branch already calls, rather than a second independent revert implementation (the record's own Gotchas below restate this as a hard constraint). Thread through the same `commit-failed` / `commit-failed-partial-revert` distinction `revertWorkMoves`'s return value already supports, so a partial revert on the mv-failure path is distinguishable from a clean one the same way it already is on the commit-failure path — e.g. `git-mv-failed` vs. a new `git-mv-failed-partial-revert` reason string.

Add regression tests in `tests/bin-lib/reconcile/archive-merged.test.js` using the existing multi-spec fixture pattern (`listSpecDirs`/two `spec-{N}/work/` subtrees, as the existing "multi-spec parent run dir" test already sets up) with an injected `runGit` failure: one test failing the second `git mv` in a 2+-pair batch (asserting the first pair's move is fully reverted, tree back at its original path in both index and disk), one test failing the commit itself on a 2+-pair batch (asserting every pair reverts, not just a single top-level pair as today's existing commit-failure test covers).

### Key Files

- `bin/lib/reconcile/archive-merged.js` — extend the `git-mv-failed` branch to revert already-succeeded pairs via `revertWorkMoves`, and adjust the failure-reason string to distinguish a partial revert
- `tests/bin-lib/reconcile/archive-merged.test.js` — add multi-pair (2+ `spec-{N}/work/`) test coverage for both the mid-batch `git-mv-failed` revert and the existing commit-failure revert path

## Gotchas

- Preserve the "never throws, degrades to a reported skip" invariant `archiveRunDir` already documents — any new revert logic must be wrapped the same way #652's `revertWorkMoves` is.
- Reuse `revertWorkMoves` (or a shared helper) rather than a second independent revert implementation — the git-mv-failure and commit-failure paths should not diverge in how they undo a batch.
