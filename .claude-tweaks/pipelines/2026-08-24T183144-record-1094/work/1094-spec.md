# 1094: feedback dedup and file-feedback.js findDuplicate both search for a marker/dedup lookup, contradicting github-write-transport.md

# Reflect — staged finding 2

**Category:** tangential

Origin: reflect light mode from #539
Defer-reason: tangential

## Current State

`plugin/skills/_shared/github-write-transport.md` states: "Never use `search_issues` (or `gh issue list --search`) for a find-by-marker/dedup lookup" -- both ride an eventually-consistent search index, which caused three real duplicate-digest incidents (#1016, #1079, #1089); the file mandates list-then-filter instead. Yet `plugin/bin/lib/feedback/file-feedback.js`'s `findDuplicate` (line ~69) does exactly the forbidden thing: `gh issue list --search <marker>` to find a prior filing by its embedded fingerprint marker. `/claude-tweaks:feedback`' Step 4's own dedup search (`gh issue list --search`) sits in the same tension, one level less severe since it is advisory (shown to a human) rather than authoritative. Both predate #539 and neither was caused by it -- #539 only narrowed what text Step 4's advisory search sends, and its own new comment now leans slightly harder on Step 8's marker lookup being reliable, which is the same lookup this contradiction concerns.

## Deliverables

Either (a) carve out a documented exception in github-write-transport.md for a marker-string lookup specifically (narrower risk profile than a free-text dedup search, since a marker is a near-unique 8-hex string), or (b) convert `file-feedback.js`'s `findDuplicate` to the mandated list-then-filter approach (`list_issues` + client-side substring match against the fingerprint marker).

## Acceptance Criteria

- [ ] `file-feedback.js`'s dedup lookup no longer contradicts (or is explicitly, narrowly exempted from) `github-write-transport.md`'s search_issues prohibition
- [ ] The three referenced incidents' failure mode (eventually-consistent index staleness) is not reintroduced by whichever fix is chosen
