# 1202: visual-decide: zero-dep serve-and-capture server primitive (bin CLI + module)

Surface: backend

## Overview

A zero-dependency, content-agnostic local server primitive for browser-based decision capture: serves a directory on loopback, accepts decision events from the served page (appended as JSONL for the agent to read next turn), and pushes SSE reload events when the served content changes. First consumer is `design-wrapper explore`'s in-browser Verdict (#1204); the primitive itself knows nothing about explore, variants, or verdicts. Ships inert — no skill invokes it until #1204 lands.

Contract freezing: this record's ACs freeze the route surface (`/events` body handling, `/stream` SSE, key gate) and #1204's conformance suite pins the event *vocabulary* on top of it. If wiring #1204 surfaces a needed shape change, the resolution is editing this module first (expand-contract), never #1204 restating shapes.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- No shell/comparison UI (#1203 owns that).
- No skill prose changes and no `_shared/visual-decision.md` (#1204 owns those).
- No HTTPS, no non-loopback binding, no multi-client session model — one human decision-maker per server instance. Concurrent sibling sessions each run their own instance with their own `--state`/`--dir` pair (upward port probing keeps instances apart; state dirs never shared).
- Not a replacement for `_shared/dev-url-detection.md` (that procedure runs project dev servers; this serves static files).

## Deliverables

- [ ] `plugin/bin/visual-decide.js` — CLI entry: `start --dir <content> --state <state-dir> [--port <n>] [--idle-minutes <n=240>]`, `stop --state <state-dir>`, `status --state <state-dir>`. `--idle-minutes` accepts fractional values (the test seam: `--idle-minutes 0.05` ≈ 3s). Default port probe base: 4173, probing upward past ports that answer.
- [ ] **Process model (pinned):** `start` self-daemonizes — spawns the server as a detached child, waits until `{state}/server-info` exists and the port answers, prints the server-info JSON to stdout, and returns to the shell. `start` against a state dir whose server is already running refuses (non-zero exit naming the running URL). `start` clears a stale `server-info`/`server-stopped` pair from a previous round before writing fresh ones.
- [ ] `plugin/bin/lib/visual-decide/` module implementing: loopback-only bind; session-key mint; `{state}/server-info` JSON (`url` with `?key=`, `port`, `pid`, `startedAt`; mode 0600); key gate — query param accepted on any request, and on first successful query-param auth the server sets `vd_key` (`HttpOnly; SameSite=Strict; Path=/`) so sub-requests (assets, `EventSource`) authenticate by cookie; static GET with path-traversal rejection and no directory listings — `GET /` and `GET /{dir}/` resolve to that directory's `index.html`, 404 when absent; `POST /events` appending one validated JSON object per request as one JSONL line to `{state}/events` (0600); `GET /stream` SSE pushing `reload` when any file under `--dir` changes (recursive mtime poll, 500ms interval); idle timeout that resets on any request and on expiry self-exits writing `{state}/server-stopped`.
- [ ] **Liveness model (pinned):** `status` reports `running` when the recorded port answers the key gate (2xx with key / 401 without); `stopped` when `{state}/server-stopped` exists and the port is silent; `crashed` when `server-info` exists, the port is silent, and no stopped marker; `never-started` when the state dir has no `server-info`. `stop` signals the recorded PID (stale-PID tolerant: dead PID → report already-stopped, exit 0) and writes `server-stopped`.
- [ ] `tests/bin-lib/visual-decide/server.test.js` + `cli.test.js` covering the Acceptance Criteria below, in-process (spawn the server on an ephemeral port inside the test).
- [ ] `docs/plugin-structure.md`: one CLI row for `visual-decide.js`, one module row for `bin/lib/visual-decide/`.

## Acceptance Criteria

1. `start` returns to the shell with the detached server running, prints the server-info JSON, and `{state}/server-info` exists with mode 0600; the `url` field contains `?key=`; a second `start` against the same state dir exits non-zero naming the running URL.
2. GET with no/wrong key returns 401 and serves nothing; GET with the key returns the static file; after one keyed request, a followup GET with the returned cookie and NO query param returns 200; a traversal attempt (`/../` resolving outside `--dir`) is rejected (non-2xx, nothing outside the dir readable); `GET /` serves `--dir`'s `index.html` and 404s when absent.
3. `POST /events` with a JSON object body appends exactly one JSONL line to `{state}/events` (asserted by line count and parseability); a malformed body returns 400 and the events file is byte-identical before/after.
4. `GET /stream` responds `text/event-stream`; touching a file anywhere under `--dir` (nested dirs included) produces a `reload` event on an open stream within 1s (2× the 500ms poll interval).
5. Server binds 127.0.0.1 only (asserted from the listening address).
6. Idle timeout (fractional `--idle-minutes` in the test) self-exits and writes `{state}/server-stopped`; any request resets the timer.
7. `stop` terminates the recorded PID and writes the stopped marker; `status` output distinguishes all four states (running / stopped / crashed / never-started) — the crashed case exercised by SIGKILLing the server in the test.
8. `npm test` passes with the new suite included; the module has zero non-builtin imports (`node:http`, `node:fs`, `node:path`, `node:crypto`, `node:child_process` only — asserted by a test greping the module's requires).

## Technical Approach

Plain `node:http` server. Key: `crypto.randomBytes` hex. Content watching: recursive mtime polling at 500ms (portable; avoid `fs.watch` platform quirks on macOS/Linux). SSE: write `retry:` + periodic `: keepalive` comments; on change emit `event: reload\ndata: {}\n\n`. Daemonization: `child_process.spawn` with `detached: true, stdio: 'ignore'` + `unref()`; the child writes `server-info` once listening; the parent polls for it, then prints and exits via `process.exitCode`.

### Data / API Surface

- `{state}/server-info`: `{"url": "http://127.0.0.1:{port}/?key={key}", "port": <int>, "pid": <int>, "startedAt": <epoch-ms>}`.
- `{state}/events`: one JSON object per line, opaque to this module (no schema validation beyond "one JSON object") — the event vocabulary belongs to `_shared/visual-decision.md` (#1204), and this module must not hardcode it.
- `{state}/server-stopped`: empty marker file.
- Routes: `GET /{path}` (static, key-gated, index.html resolution), `POST /events`, `GET /stream`. Cookie: `vd_key`. Exact status codes per Acceptance Criteria.

## Gotchas

- Use `process.exitCode`, never `process.exit()` after a stdout/file write — a truncated write on exit is an observed failure class in this repo (async write-vs-exit race).
- Events are user input: append verbatim JSON, never interpret; never log or echo the session key (server-info is the only place it lives, mode 0600).
- The event body is deliberately schema-opaque here — validating vocabulary in this module would couple it to the contract file and break the layering (`_shared/visual-decision.md` owns vocabulary; consumers validate).
- mtime polling over `fs.watch`: `fs.watch` is unreliable/coalescing on macOS and this repo's tests run on macOS + Linux CI.
- PID reuse after a crash is an accepted residual risk (state dirs are per-round and short-lived); `status`'s port-probe liveness, not the PID, is the authority — that is why the crashed state is defined by port silence, not PID absence.
- Test the idle timer with fractional `--idle-minutes`, not real minutes — no long-running CI tests.
