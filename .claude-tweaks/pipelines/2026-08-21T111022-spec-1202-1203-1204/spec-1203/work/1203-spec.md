# 1203: design-wrapper compare-shell: comparison template + seeder (live + durable modes)

Surface: web
Design-intent: minimal, delightful

## Overview

The comparison shell for explore's variant tournaments: one self-contained HTML template plus a seeder script that stamps variants into it. Two output modes — **live** (iframes reference files served by the `visual-decide` primitive (#1202); verdict bar POSTs events; SSE client auto-reloads on re-seed) and **durable** (every variant embedded via `srcdoc`, verdict bar inert, outcome metadata stamped; the page opens from `file://` forever as the round's design-decision record). Template-plus-seeding is the `/design` canvas strategy, minus the editor. Ships inert — nothing invokes the seeder until #1204 lands.

**Contract ordering, stated plainly:** this unit ships BEFORE #1204 (which is blocked by it). The four verdict event shapes in AC 3 are the frozen convention from the parent's design (#1201); #1204 then canonicalizes them into `_shared/visual-decision.md` and pins both sides with its conformance suite. If #1204's authoring surfaces a needed divergence, the resolution is editing this template's serializer then — never restating shapes in prose. The `/events` + `/stream` wire contract this template's client targets is frozen by #1202's own Acceptance Criteria.

**Schema ownership:** this unit's durable-mode output is the canonical owner of `decision.html`'s shape (the metadata block and embedding structure). Explore's Lock-in (#1204) supplies the manifest; it never defines the file format.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- No server code (#1202 owns serving and event capture).
- No skill prose changes (#1204 rewires explore).
- No tweak levers, no pan/zoom canvas (explicitly deferred by the parent's Decision Rationale).
- The shell is tooling chrome, not a design deliverable — it must never visually compete with the variants it frames (system font stack, recessive neutral styling; `Design-intent: minimal, delightful` means restrained chrome with one well-placed micro-interaction on the recorded-state confirmation, not decoration).

## Deliverables

- [ ] `plugin/skills/design-wrapper/compare-shell/template.html` — self-contained page with:
  - **Grid overview:** every variant in a sandboxed iframe (`sandbox="allow-scripts"` — no `allow-same-origin`; variants may carry their own JS/motion; the host page alone owns event POSTing and the SSE client), display name docked per frame; clicking a frame selects it (visible selection ring). Degraded slots rendered, labeled with their failure reason, never selectable. A visible note directs fine typographic judgment to the focus view (grid frames render scaled down).
  - **Focus view:** one variant full-viewport; ArrowLeft/ArrowRight and click advance the cycle; Esc returns to grid; a docked "{i} / {N} — {display name}" indicator counts every slot including degraded ones (which show their label and stay unpickable).
  - **Verdict bar:** Pick this / Reroll / Steer (one-line text input) / Exit without pick. **Pick targets the focused variant in focus view, or the grid-selected variant in grid view, and is disabled when neither exists.** Each control POSTs one JSON event to `/events`; on success the page flips to a recorded-state view ("recorded — return to the terminal").
- [ ] `plugin/skills/design-wrapper/compare-shell/seed-compare.mjs` — takes `--manifest <json>` + `--mode live|durable` + `--out <path>`. **Path convention:** `sharedMarkup` and `variants[].files` are paths relative to the manifest's own directory (the explore round dir), used verbatim as server-relative iframe `src` URLs in live mode.
- [ ] Live mode output: iframes `src`-reference the served variant files; verdict bar POSTs to `/events`; SSE client subscribes to `/stream` and reloads on `reload`.
- [ ] Durable mode output: every variant embedded via `srcdoc`. **Identity scope mechanics:** `variants[].files` holds only that variant's skin CSS path; the seeder reads `sharedMarkup` once and emits one srcdoc document per variant = shared markup with that skin's CSS inlined in a `<style>` block. Layout scope: each variant's own markup embedded as its srcdoc. Verdict bar rendered **inert: buttons carry `disabled` attributes and the mode flag gates listener attachment — no handlers attached in durable mode.** Metadata block stamps the outcome; page functions from `file://`.
- [ ] Seeder refusals (non-zero exit, named error): manifest names a missing artifact file; duplicate variant ids; durable mode without an outcome; `outcome.winner` not found among `variants[].id`. Size warning (stderr, still writes) when the emitted `--out` file exceeds 2 MB — measured on the final output file's byte size, both modes.

## Acceptance Criteria

1. Live-mode output contains one iframe per manifest variant referencing its served path, a form/handler POSTing to `/events`, and an `EventSource("/stream")` subscription — asserted structurally by parsing the emitted HTML.
2. Durable-mode output contains zero occurrences of `http://` or `https://` (fully self-contained — no CDN, no external fonts), embeds every variant's content (fixture sentinel strings from each variant found in the output), and stamps the outcome metadata block (winner id, seed key, reroll count, steer history, date all present).
3. Event payloads emitted by the verdict bar are exactly the four shapes `{"type":"pick","variant":id}`, `{"type":"reroll"}`, `{"type":"steer","text":...}`, `{"type":"exit"}` plus a `ts` field — asserted on the template's single serializer function (browser behavior is not testable here; the serializer is).
4. A degraded variant (manifest flag) renders with its failure reason and a disabled/non-selectable marker in BOTH views; the focus-view indicator's `{N}` counts it; the pick control cannot target it (asserted structurally).
5. Refusal cases (missing file, duplicate id, missing outcome, unknown `outcome.winner`) exit non-zero naming the offending variant/field; the 2 MB warning appears on stderr while the file is still written.
6. Both scope shapes seed correctly: an identity fixture (1 markup + 3 skins) and a layout fixture (3 markups) each produce 3 variant frames; each identity-scope srcdoc contains the shared markup's sentinel AND its own skin's sentinel, not a sibling skin's.
7. Embedded variant content cannot break out of the host page: quoting/escaping asserted with a fixture variant containing `</textarea></iframe>"'` sentinels.
8. Durable-mode verdict buttons carry `disabled` and no listener-attachment code path runs under the durable mode flag (asserted structurally on the emitted page).
9. Focus view carries the "{i} / {N} — {name}" indicator and grid view carries per-frame selection affordances — asserted structurally.
10. `npm test` passes with the new test included.

## Technical Approach

The template is a single HTML file with inline CSS/JS and two placeholder blocks the seeder replaces (variant data as a JSON island; mode flag). Seeder is plain Node ESM (`.mjs`), builtins only, argv parsing by hand — refuse bad input loudly, print one summary line. Escape embedded content for `srcdoc` (HTML-attribute escaping) and for the JSON island (`<` escaped).

### Data / API Surface

Manifest schema (JSON): `{scope: "identity"|"layout", seedKey, rerollCount, steerHistory: [..], sharedMarkup?: path (identity scope), variants: [{id, name, files: [path...], degraded?: bool, reason?: str}], outcome?: {winner, date}}` — all paths relative to the manifest's directory. Event shapes: see AC 3; canonicalized later by #1204 into `_shared/visual-decision.md`, whose conformance test pins this serializer. `decision.html`'s format (metadata block field set + embedding structure) is owned HERE — #1204 pins it, never redefines it.

## Gotchas

- `srcdoc` content is attribute-escaped, not element-escaped — `&quot;` matters, `</iframe>` inside content does not close anything but `"` does end the attribute. Test with hostile sentinels (AC 7).
- The JSON island needs `<` escaping or an embedded `</script>` in variant content ends the island.
- Live mode's iframe `src` must stay relative (the visual-decide server serves the explore dir at `/`) — absolute `file://` paths would bypass the server and break the key gate.
- System font stack only — the durable file must not depend on any network fetch (AC 2's zero-`http` grep is the enforcement).
- Keep the shell's own chrome recessive: no color that competes with variant frames; the one `delightful` touch belongs on the recorded-state confirmation, nowhere else.
- Do not hardcode the event vocabulary anywhere except the one serializer function — #1204's conformance test pins that function's output against `_shared/visual-decision.md`.
- `sandbox="allow-scripts"` without `allow-same-origin` is deliberate: variant JS runs, but frames get an opaque origin and cannot reach the host page, its key cookie, or the server.
