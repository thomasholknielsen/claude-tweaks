# 1153: fetch-sub-issues.js: fold retry resolution + canonicalization behind the CLI

Origin: reflect hindsight from #1097
Defer-reason: tangential

## Current State

`bin/fetch-sub-issues.js` returns a `{byParent, retry}` envelope and leaves retry resolution (per-parent `gh api --paginate` REST calls), failure capture, and canonicalization to its callers — three near-copy `node -e` prose snippets in `_shared/trust-table.md` and `_shared/github-pr-scan-acceptance.md` (acceptance-gap + parent-gate), each with its own tmp-file names. During #1097's own pipeline, one fix round and a three-finding staged patch all arose in exactly those prose copies — the triplication is where the defects live.

## Deliverables

- A CLI flag (e.g. `--resolve-retries`) that performs the per-parent REST retries internally (paginated, loud failure naming the parent) and emits the final resolved envelope — flat canonicalized array and/or per-parent map — so each prose site collapses to one command plus a thin assembly snippet.
- Migrate the three prose sites to the flag; retain the probe-unavailable REST fallback blocks unchanged.
- Unit tests for the retry path via the injectable runner.

## Acceptance Criteria

- Each of the three prose sites carries no retry-ladder `node -e` snippet — one CLI invocation plus at most a thin write/compose step.
- A retry parent whose REST call fails still fails the run loudly naming the parent, from inside the CLI (exit 3), covered by a test.
- `npm test` passes including the prose conformance suites.
