# 271: code-health focus mode: candidate-driven scoping with a dead-code candidate generator

Surface: backend
Parent: #265

## Overview

The verticals framework and its first vertical, shipped together so the framework never exists consumer-less (IL-02): `code-health focus=<vertical>` swaps the sweep's **scoping strategy only** — deterministic repo-wide candidate generation feeding the LLM judge, instead of `next-slice` directory rotation — while everything downstream (classify, judge, verify gate, staleness re-check, fingerprint, dedup, wontfix suppression, filing) runs unchanged. First vertical: `dead-code` — a candidate generator that finds unreferenced exports and orphaned files, judged by the existing `dead-code` criterion. This gives the "dedicated daily pass" shape the slice rotation can't: dead code across the whole repo every firing, not one directory per visit.

Valuable standalone under full supervision — focus runs file records exactly like today's sweeps. Decision rationale on parent #265.

**Complexity:** High
**Estimated tasks:** 8

## Non-Goals

- The other three verticals (test-hygiene, abstraction-police, experiment-cleanup) — separate leaves, blocked on this framework.
- Any change to the judge, verify gate, dedup, filing, or the criteria catalog — `dead-code` already exists as a criterion.
- Fleet provisioning/cadence (fleet leaves); machine-granting (grant leaves). Focus-mode findings flow through the standard supervised path until those ship.
- Non-JS/TS candidate coverage (the generator states its coverage; other languages are a later widening).

## Technical Approach

Reference analysis: static scan — collect export declarations (`export`/`module.exports` grep-anchored per the bounded-read patterns SKILL.md already uses), then search for import/require references repo-wide via `find`+`xargs grep` (NOT bare recursive grep, which honors `.gitignore` differently across tools — use the explicit file-list approach and a control grep, per the recursive-grep-skips-gitignored-files lesson). No AST dependency in v1 — grep-anchored heuristics with the false-negative direction chosen deliberately: **prefer missing a dead export over flagging a live one**; the judge is the second filter, the verify gate the third.

## Gotchas

- Never test by running `bin/code-health.js` with real arguments — it pushes durable state to the shared `health-state` branch and stamps a 90-day rotation cursor (IL-73). Exercise the module and its unit suite only.
- A NUL byte or encoding oddity in a scanned file makes grep go silent while reads succeed — the generator must tolerate binary-ish files by skipping them explicitly, and the fixture suite includes one (the NUL-byte lesson).
- `{result}`-style token greps can't match populated text (IL-79) — reference detection must search the bare symbol name, word-bounded, not a decorated pattern.
- The focus mode's scoping swap must not touch the rotation cursor or content-hash state — a focus firing is cursor-neutral (the generalist rotation's state belongs to the generalist); state this in SKILL.md and assert the state files untouched in the fixture-level test if reachable.
- Sweep SKILL.md prose for slice-assumptions that become wrong under focus mode ("the slice", "this directory") — the same fact restated in multiple sections drifts (IL-17); read the whole file, don't keyword-grep.
