# 1078: Add artifacts residue probe: 30-day retention and legacy-root relocation findings

Surface: backend

## Current State

`plugin/bin/residue.js` wires six probes from `plugin/bin/lib/residue/probes/` (worktrees, branches, forge, suite, release, pipeline-runs; requires at lines 15-20). `plugin/bin/lib/residue/finding.js:11` freezes the kind enum: `KINDS = ['worktree', 'branch', 'pr', 'suite', 'release', 'pipeline-run']` — a finding with any other kind fails validation. The per-finding `scope` field is a separate frozen vocabulary: `'blast-radius'` or `'observed'` (`finding.js`) — distinct from the CLI's `--scope repo|blast-radius` filter flag namespace (`scope-filter.js`), and `filterResultsByScope` keeps only `scope: 'blast-radius'` findings under `--scope blast-radius`.

No probe covers QA artifacts: after #1077 (the relocation sub-issue in this same decomposition) lands, artifact dirs accumulate indefinitely under `.claude-tweaks/artifacts/`, and legacy project-root `screenshots/`/`traces/` trees linger in existing projects with no cleanup path. `plugin/skills/visual-review/journey-mode.md:117` currently states "There is no automatic retention policy; users manage cleanup" — true today, false once this ships. `/tidy`'s Step 6 routing already auto-applies a Delete row for "stale temp files, broken symlinks, …" at every aggressiveness tier (`step-6-auto.md`; `step-6-interactive.md` carries no routing table of its own — it defers to `step-6-auto.md`'s by reference). `/tidy` Step 4.5 invokes `bin/residue.js` with `--scope repo`, so it surfaces these findings; `/wrap-up`'s residue sweep passes `--scope blast-radius` and will **never** surface them — deliberate, since aged artifacts are repo-level housekeeping unattributable to the current run (rationale on parent #1075). `/tidy` is the sole surfacing consumer.

## Deliverables

1. New probe `plugin/bin/lib/residue/probes/artifacts.js`, following `pipeline-runs.js`'s contract shape (`{ran, reason, findings[]}`, `makeFinding`, `mainCheckoutRoot` anchoring) generalized to **five independent roots**: `.claude-tweaks/artifacts/screenshots/qa/`, `.claude-tweaks/artifacts/screenshots/browse/`, `.claude-tweaks/artifacts/traces/` (aged-dir class) and project-root `screenshots/`, `traces/` (legacy class). Each root gets its own `readdirSync` with its own ENOENT branch — a missing root is per-root clean, never a probe failure; findings aggregate across all readable roots. Any **non-ENOENT** read failure on any root makes the whole probe `{ran: false, reason}` with the reason naming every failed root — a partial scan is never reported as a clean sweep, matching the sibling probes' fail-loud contract. Two finding classes, both `kind: 'artifact'`, both `scope: 'observed'`:
   - **Aged artifact dir** — a first-level entry under one of the three artifacts roots whose newest contained file (recursive, by mtime; falling back to the dir's own mtime when it contains zero files) is older than 30 days. `remedy: 'auto'`. Evidence names the age in days and the newest file.
   - **Legacy root residue** — a project-root `screenshots/` or `traces/` directory (the pre-relocation convention), flagged whenever present. `remedy: 'auto'` when the tree passes the same 30-day newest-file rule; `remedy: 'record'` when it contains anything fresher — a trace captured the day before the plugin update must surface for human disposition, not auto-delete. Evidence names it relocation residue superseded by `.claude-tweaks/artifacts/`.
2. `'artifact'` added to `finding.js`'s frozen `KINDS`. The `scope` vocabulary is **not** extended — `'observed'` is the semantically correct existing value (cross-run, not this-run-attributable). Both finding classes deliberately share the one `kind`; discrimination is by evidence text (`render.js` renders `f.kind` generically, so no per-kind branching exists to feed).
3. Probe wired in `plugin/bin/residue.js` alongside the six existing requires/invocations.
4. Test suite `tests/bin-lib/residue/artifacts.test.js` (new), matching the sibling suites' conventions in that directory.
5. `/tidy` routing prose: `step-6-auto.md` names `artifact` findings in the existing auto-apply Delete row ("stale temp files" class) and notes the `remedy: 'record'` legacy case routes as a stage/judgment item, not auto-delete; `step-6-interactive.md` needs no edit (no routing table of its own — verify, don't assume); `tidy/SKILL.md`'s Step 4.5 data-source row (line 82's parenthetical kind list) mentions the new kind.
6. `plugin/skills/visual-review/journey-mode.md:117`: replace the "There is no automatic retention policy; users manage cleanup" sentence with one stating the actual contract — artifacts older than 30 days are surfaced for deletion by `/tidy`'s residue sweep via the `artifact` residue finding.

## Acceptance Criteria

- Probe returns `{ran: true, reason: null, findings: []}` when none of the five roots exist.
- Partial-presence fixture: artifacts root exists with only one of the three subdirs (e.g. only `screenshots/browse/`) — missing siblings are silently clean, findings still come from the present one.
- A fixture dir whose newest file mtime is >30 days old yields one `kind: 'artifact'`, `scope: 'observed'`, `remedy: 'auto'` finding; a fixture dir with an old dir mtime but one fresh file yields none (the discrimination case).
- An empty first-level dir (no contained files) older than 30 days by its own mtime yields a finding (empty dirs must not be immortal).
- A project-root `screenshots/` or `traces/` fixture yields a legacy-residue finding: `remedy: 'auto'` when its newest content is >30 days old, `remedy: 'record'` when it contains a fresh file.
- An unreadable root (permissions, non-ENOENT) yields `{ran: false, reason}` naming the failed root, even when other roots were readable.
- `makeFinding` validation passes for every emitted finding (`kind: 'artifact'` accepted after the KINDS change; `scope: 'observed'`; all required fields non-empty).
- Tests set fixture mtimes explicitly via `fs.utimesSync` — no reliance on filesystem defaults or sleeps.
- `node --test tests/bin-lib/residue/` passes; full `npm test` passes.

## Technical Approach

Mirror `pipeline-runs.js` structurally per root: resolve the scan base via `mainCheckoutRoot(cwd) || cwd`, then loop the five roots with per-root `readdirSync` and the ENOENT-vs-other-error split from Deliverable 1. The 30-day threshold is a module constant (`THIRTY_DAYS_MS`) — deliberately not a policy key (decision rationale on parent #1075). Newest-file resolution: walk each first-level entry recursively collecting the max file mtime; zero files falls back to the entry's own dir mtime. `Date.now()` is fine here (plugin runtime code). `scope: 'observed'` keeps these findings out of `--scope blast-radius` consumers by construction — verify against `scope-filter.js`'s tests rather than re-deriving.

## Gotchas

- **Blocked by #1077** (encoded as a native GitHub issue dependency, `work-links: native` — deliberately no body-text `Blocked by #N` line; dispatch reads the native graph): the probe's path constants are the **post-relocation** paths. Building against the pre-relocation layout bakes wrong constants into a shipped probe.
- Open records #1026, #951, #918 are actively reworking scope semantics in sibling probes and touch `tests/bin-lib/residue/` — new files here don't collide, but re-verify the `scope: 'observed'` choice against whatever those fixes land.
- Tests must inject mtimes via `fs.utimesSync`, never sleep.
- `render.js` renders `f.kind` generically with no per-kind branching — verify no change is needed there rather than assuming.
- The empty-dir fallback (dir mtime when zero files) is easy to forget and makes empty run dirs immortal without it — it has its own acceptance criterion.
- The auto-apply Delete row's reversibility class (deletion of gitignored, untracked, declared-transient files at every tidy tier) was an explicit design decision for **aged** artifacts (parent #1075); the `remedy: 'record'` split for fresh-content legacy roots exists precisely because that confidence does not extend to content that may be days old.
