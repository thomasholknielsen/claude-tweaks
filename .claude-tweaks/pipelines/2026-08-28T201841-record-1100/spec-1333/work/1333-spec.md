# 1333: wrap-up standalone run creation: friction-events.js can't backfill a torn-down non-EnterWorktree session

Surface: infra

## Current State

`stampAdHocRunDir` (`plugin/bin/lib/hooks/post-tool-use.js`, record #500) mints a lightweight ad-hoc run directory so a session's gate denials, sandbox refusals, and `AskUserQuestion` stops have somewhere to log to before a formal pipeline run dir exists. It only fires when `ctx.input.tool_name === 'EnterWorktree'` — the plugin's own worktree-entry tool. `findRunsByWorktreePath` (the read side `friction-events.js` and `/claude-tweaks:reflect`'s Friction lens use) can only backfill an earlier session's friction into a later standalone `/claude-tweaks:wrap-up` run by matching a stamped run dir's `worktree` field against the current worktree path.

When a session's worktree is instead created by a different tool — another plugin's own worktree-management skill, or a raw `git worktree add` run directly via Bash — `EnterWorktree` never fires, so `stampAdHocRunDir` never runs, and no ad-hoc run dir is ever minted for that session. There is nothing for a later standalone wrap-up's Friction lens to find, even in principle, once that worktree is torn down. This is a different root cause than #1117, which covers auto-archival racing the read for run dirs that *were* stamped — here, no run dir is ever created to race against.

## Deliverables

- Widen `stampAdHocRunDir`'s trigger in `plugin/bin/lib/hooks/post-tool-use.js` so it also fires the first time a session's `ctx.cwd` resolves to a worktree path (per `git worktree list --porcelain`, parsed via the existing shared `parseWorktreeList` from `worktree-reap.js`) that isn't the main repo root — not only when `tool_name === 'EnterWorktree'`.
- Preserve every existing safety property of `stampAdHocRunDir` unchanged: skip when `ctx.ownedRun.dir` is already set, never clobber a different session's already-written ownership (the same-second-collision guard), best-effort `rollbackMint` on a `writeRunState` failure, and the blanket `catch { /* never break a session over bookkeeping */ }`.
- Gate the new, non-`EnterWorktree` detection so it does not run `git worktree list` on every single tool call for every session — stamp (or determine "not a worktree, skip") at most once per session, since this hook fires on every `PostToolUse` event across every session in the harness.
- Update the doc comment above `stampAdHocRunDir` and, if it names the `EnterWorktree`-only trigger, `plugin/skills/reflect/full-mode.md`'s Friction lens section and `docs/hooks.md`, so the documented trigger condition matches the widened behavior.

## Acceptance Criteria

- A session whose worktree is created by a tool other than `EnterWorktree` (a raw `git worktree add` via Bash, or a stand-in for a third-party tool call) ends up with an ad-hoc run dir stamped — `worktree` set to the resolved path, `sessionId` set to the session's id — by the next `PostToolUse` hook invocation in that worktree.
- `friction-events.js --run <dir>` (the same lookup `/claude-tweaks:reflect`'s Friction lens performs) subsequently returns friction events logged during that earlier, non-`EnterWorktree` session.
- A session that already owns a run dir (a formal `/claude-tweaks:build`/`/claude-tweaks:flow` pipeline run) never gets a second, competing ad-hoc run dir stamped, regardless of which tool created its worktree.
- The existing `EnterWorktree`-triggered stamping path, and its same-session/no-clobber/no-double-stamp guards, are unaffected — `tests/hooks-post-tool-use-adhoc-rundir.test.js` and `tests/hooks-gate-coverage.test.js` continue to pass unmodified in their existing assertions.
- New test coverage in `tests/hooks-post-tool-use-adhoc-rundir.test.js` exercises the non-`EnterWorktree` stamping path directly, including a case that confirms `git worktree list` is not invoked on every ordinary (non-worktree, or already-stamped) tool call.
- A session running from the main checkout (not any worktree) never gets a spurious ad-hoc run dir stamped.

## Technical Approach

Widen the guard at the top of `stampAdHocRunDir` (`plugin/bin/lib/hooks/post-tool-use.js:394`) from an unconditional early-return on `ctx.input.tool_name !== 'EnterWorktree'` to: continue past the guard when either the tool name is `EnterWorktree` (existing path, unchanged) or `ctx.cwd` resolves to a worktree entry distinct from the main repo root per `git worktree list --porcelain`. Reuse `resolveCreatedWorktreePath`'s existing porcelain-fallback branch (`plugin/bin/lib/hooks/post-tool-use.js:352`) for this lookup rather than duplicating the `parseWorktreeList` call — its `EnterWorktree`-tool-response-text fast path stays the first attempt only when `tool_name === 'EnterWorktree'`; every other tool name skips straight to the porcelain-based lookup, since there is no `tool_response` shaped like an `EnterWorktree` result to parse in that case.

Cache the "checked this session already" state to avoid running `git worktree list` on every `PostToolUse` call — for example, short-circuit once `ctx.ownedRun.dir` is set (already checked first, existing behavior) or once this session has already minted (or definitively ruled out) an ad-hoc stamp, tracked the same way `existing.sessionId` ownership is already tracked today.

### Key Files

- `plugin/bin/lib/hooks/post-tool-use.js` — widen `stampAdHocRunDir`'s trigger condition; reuse `resolveCreatedWorktreePath`'s porcelain fallback for non-`EnterWorktree` tool calls
- `tests/hooks-post-tool-use-adhoc-rundir.test.js` — add coverage for the non-`EnterWorktree` stamping path and the per-session rate-limit
- `plugin/skills/reflect/full-mode.md` — update the Friction lens's description of the stamping trigger if it names `EnterWorktree` specifically
- `docs/hooks.md` — update `stampAdHocRunDir`'s documented trigger condition

## Gotchas

- Calling `git worktree list --porcelain` unconditionally on every `PostToolUse` event (for every tool, every turn, every session) is a real perf cost — the fix must gate this to at most once per session, not run it on every hook invocation.
- The widened trigger must only fire when `ctx.cwd` genuinely resolves to a worktree entry distinct from the main repo root — never for an ordinary main-checkout session, or every non-worktree session would get a spurious ad-hoc run dir.
- `resolveCreatedWorktreePath`'s `EnterWorktree`-tool-response-text fast path only applies when `tool_name === 'EnterWorktree'`; for any other tool name there is no matching `tool_response` shape to parse, so the generalized code path must go straight to the porcelain-based lookup and must not attempt to parse a non-`EnterWorktree` `tool_response` for the sentinel path text.
- This does not close #1117 (auto-archival racing the read for run dirs that *were* stamped) — a different root cause; don't conflate the two fixes in the same change.
