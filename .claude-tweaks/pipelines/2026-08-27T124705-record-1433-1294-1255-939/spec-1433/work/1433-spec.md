# 1433: wrap-up's unattended consoleAutoResolve merge path never applies merge-check's agent-instruction floor

Surface: backend

## Current State

During #1108's wrap-up, self-invoking `assess-agent-autonomy merge-check` as extra due
diligence on a docs-only PR touching `plugin/skills/_shared/scratch-worktree.md` returned
`needs-human` — the change was a genuine behavior-changing correction, and
`merge-check.md`'s calibration table explicitly treats this class of edit as `needs-human`
even when small and factually correct.

`merge-check` is wired into only two call sites: `/dispatch`'s Auto-merge gate and
`wrap-up/review-console.md`'s "Auto-merge short-circuit" section (the `auto:merge`-label or
`manifesto-authorized-merge.md` lever path). The separate "Auto-resolution short-circuit"
section further down `review-console.md` (`consoleAutoResolve`, keyed on
`autonomy: unattended`) never calls `merge-check` at all — once `/review` has passed, it
resolves the merge decision to "merge" unconditionally, with no re-check of the
agent-instruction-file floor or the sensitive-path floor that `merge-check.md` otherwise
treats as hard, unoverridable gates (an agent-instruction file is `needs-human` unless a
refutation attempt clears it; a sensitive-path hit renders `needs-human` with nothing else
weighed).

This means a project running at `autonomy: unattended` can currently auto-merge an edit to a
widely-cited shared skill contract (e.g. `_shared/*.md`) with none of `merge-check`'s extra
scrutiny, even though the exact same edit shape would be blocked `needs-human` if it had
arrived via the `auto:merge`-label path instead. Nothing in `review-console.md` states
whether this asymmetry is deliberate.

## Deliverables

- [ ] Decide whether the `consoleAutoResolve` (`autonomy: unattended`) Auto-resolution
      short-circuit in `plugin/skills/wrap-up/review-console.md` should apply
      `merge-check`'s agent-instruction-file floor (and/or sensitive-path floor) before
      resolving the merge decision to "merge"
- [ ] If yes: wire a `merge-check` invocation (or an equivalent narrower floor check) into
      that short-circuit, and document the change inline in `review-console.md`
- [ ] If no (by design): add one sentence to `review-console.md`'s "Auto-resolution
      short-circuit" section stating explicitly that `/review`'s pass is the sole
      content-judgment gate at this tier, so a future reader doesn't rediscover this same
      question

## Acceptance Criteria

1. `plugin/skills/wrap-up/review-console.md`'s "Auto-resolution short-circuit
   (`consoleAutoResolve`)" section states explicitly, one way or the other, whether an
   agent-instruction-file edit gets any content-judgment scrutiny beyond `/review`'s own
   pass before an `unattended`-tier run auto-merges it.
2. If the decision is "wire it in," the short-circuit calls `merge-check` (or the narrower
   equivalent) before merging, and a `needs-human` verdict from that call causes the run to
   fall back to the ordinary `pending-review` park instead of merging unconditionally.

## Technical Approach

Read `plugin/skills/wrap-up/review-console.md`'s "Auto-resolution short-circuit
(`consoleAutoResolve`)" section and `plugin/skills/assess-agent-autonomy/merge-check.md`'s
calibration table and hard-floor rules side by side. Compare against the "Auto-merge
short-circuit" section in the same file, and `dispatch/SKILL.md`'s group-scoped Auto-merge
gate, to confirm both of those paths do call `merge-check` and only the `consoleAutoResolve`
path skips it.

If wiring it in: add a `merge-check` invocation inside the `consoleAutoResolve` branch,
gated the same way the "Auto-merge short-circuit" section gates it, and route a
`needs-human` verdict to the same fallback the ordinary (non-auto-resolved) path uses when
it doesn't merge (leaving the run at `pending-review`, PR left open under `pr-first`). Log
the verdict to `decisions.md` the same way other `consoleAutoResolve` resolutions already
are, per the file's own logging convention.

If declining: add the single clarifying sentence to the same section, naming `/review`'s
pass as the sole content-judgment gate at this tier by design.
