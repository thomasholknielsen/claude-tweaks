# 1026: residue.js --scope blast-radius doesn't filter branches/pipeline-runs by worktree ownership

Surface: backend

Origin: discovered during record #212's /claude-tweaks:wrap-up (Phase 3 residue sweep)
Defer-reason: tangential

## Current State

`plugin/bin/lib/residue/probes/branches.js` and `plugin/bin/lib/residue/probes/pipeline-runs.js` unconditionally tag every finding `scope: 'blast-radius'` -- neither probe ever emits `scope: 'observed'`. `plugin/bin/lib/residue/scope-filter.js`'s comment states that `--scope blast-radius` "narrows to findings whose own `scope` field is 'blast-radius', dropping `observed` findings (a sibling worktree, another lane's PR)" -- but for these two probes there is no `observed` case to drop, so `--scope blast-radius` is a no-op for them: every merged-but-undeleted branch and every unarchived `status: clean` pipeline run dir in the *entire repo* is reported, regardless of which record's worktree produced it.

`wrap-up/residue-sweep.md` (the sole caller that passes `--scope blast-radius`, deliberately overriding the CLI's own `--scope repo` default) documents the opposite behavior: "a finding belongs on this run's ledger only if it is this run's own blast radius (a branch this run's worktree left behind, a PR from this run's own head branch...)". Observed live: a residue sweep run during record #212's wrap-up (worktree `record-212`) returned merged branches `worktree-record-548` and `worktree-record-744`, plus two other records' unarchived pipeline-run directories (`2026-08-20T044329-record-631`, `2026-08-20T064458-record-744`) -- none belonging to record #212's own work.

Only `plugin/bin/lib/residue/probes/forge.js` (the PR probe) actually discriminates ownership (`scope: mine ? 'blast-radius' : 'observed'`).

## Deliverables

1. Give `branches.js` and `pipeline-runs.js` the same ownership discrimination `forge.js` already has -- tag a branch/pipeline-run `blast-radius` only when it can be attributed to the invoking session's own worktree/run (or leave both `blast-radius` when genuinely unattributable, but document why blast-radius scope can't apply to that probe rather than letting the doc's promise silently not hold).
2. Update `wrap-up/residue-sweep.md` if the resolved behavior differs from what it currently promises, so the doc and the code agree.
3. Add a regression test pinning that `--scope blast-radius` actually drops a branch/pipeline-run belonging to a different worktree/record than the one the CLI was invoked against.

## Acceptance Criteria

- A residue sweep run with `--scope blast-radius` from worktree X reports zero branch/pipeline-run findings attributable to worktree Y's own work, when X and Y are unrelated.
- `wrap-up/residue-sweep.md`'s stated behavior matches the CLI's actual behavior for every probe it invokes with this scope.
- Existing `--scope repo` behavior (used by `/tidy`) is unchanged.

## Technical Approach

Model `branches.js`'s and `pipeline-runs.js`'s ownership discrimination on `forge.js`'s existing `scope: mine ? 'blast-radius' : 'observed'` pattern: for branches, derive "mine" from reachability against this run's own worktree HEAD history or its known branch-naming convention (see #918, which covers exactly this gap for `branches.js` alone); for pipeline-run directories, derive "mine" from whichever run-dir-to-worktree attribution the directory's own `config.yml`/`decisions.md` already records (e.g. the run-id embeds the record number the sweep was invoked for). Where attribution genuinely cannot be determined for a given finding, leave it `blast-radius` but add a comment in the probe explaining why that probe can't discriminate, rather than letting `scope-filter.js`'s and `residue-sweep.md`'s promised behavior silently not hold for it. Reconcile `wrap-up/residue-sweep.md`'s stated guarantee against whatever the two probes end up actually doing once fixed.

### Key Files

- `plugin/bin/lib/residue/probes/branches.js` — no ownership discrimination (also #918's scope)
- `plugin/bin/lib/residue/probes/pipeline-runs.js` — no ownership discrimination
- `plugin/bin/lib/residue/probes/forge.js` — reference pattern (`scope: mine ? 'blast-radius' : 'observed'`)
- `plugin/bin/lib/residue/scope-filter.js` — header comment states the guarantee both probes currently violate
- `plugin/skills/_shared/residue-sweep.md` (`wrap-up/residue-sweep.md`) — the sole `--scope blast-radius` caller; update if resolved behavior differs
- `tests/bin-lib/residue/` — new regression tests for both probes
