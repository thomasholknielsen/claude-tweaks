# 1305: sweep-shadow: entry-gate stat/lstat calls still swallow non-ENOENT errors silently

Defer-reason: tangential
Surface: backend

## Current State

`plugin/bin/lib/hooks/sweep-shadow.js`'s entry-gate checks — `fs.statSync(shadowStaged)` (guarding the staged/ relocation block) and `fs.lstatSync(shadowDecisions)` (guarding the decisions.md relocation block) — are both wrapped in bare `try { } catch { /* nothing to sweep */ }` blocks that treat ANY thrown error as "target doesn't exist, clean no-op," not just `ENOENT`. `stat`/`lstat` only need traversal (execute) permission on the parent directories, not the target itself, so a permission-denied condition one level up the shadow path (or `ENOTDIR`/`ELOOP`/`EIO`) still silently produces `diagnostic: false` — the exact silent-partial-failure category #1171 fixed for the readdir/relocation blocks below these gates, but left untouched here since it wasn't in #1171's named line ranges.

Found during #1171's build review (adversarial code review of that fix, confirmed by re-reading the code — not yet reproduced with a live permission-denial test, since it requires denying traversal on a PARENT directory rather than the target itself, a different chmod target than #1171's own tests use).

## Deliverables

- Distinguish an actual `ENOENT` (nothing to sweep — correct clean no-op) from any other stat/lstat failure (parent-dir permission denial, `ENOTDIR`, `ELOOP`, `EIO`, etc.) at both entry gates, surfacing the latter as a `sweep: failed to check for shadow {staged/|decisions.md} — {code}` diagnostic line, matching the pattern #1171 established for the readdir/relocation blocks.
- A regression test: a permission-denied PARENT directory (not the target itself) produces a diagnostic, not a silent clean sweep, for both the staged/ and decisions.md gates.

## Acceptance Criteria

- A stat/lstat failure other than ENOENT at either entry gate produces a visible `sweep:` diagnostic line, not a clean-sweep report.
- A genuine ENOENT (target doesn't exist) still behaves as a clean no-op, unchanged.
- `npm test` passes.

## Technical Approach

Mirror #1171's own fix shape: check `err.code === 'ENOENT'` explicitly in each catch block; only that code short-circuits to "nothing to sweep." Any other code pushes a `sweep: failed to check for shadow {target} — {code}` line (setting `diagnostic: true` via the existing `sweep:`-prefix convention) and skips that block's relocation logic, same as a genuine absence would, but visibly.

### Key Files

- `plugin/bin/lib/hooks/sweep-shadow.js` — the `fs.statSync(shadowStaged)` gate and the `fs.lstatSync(shadowDecisions)` gate
- `tests/bin-lib/hooks/sweep-shadow.test.js` — #1171's new test file; the new regression test belongs alongside it

## Gotchas

- To trigger this specific failure mode in a test, chmod the PARENT of the target (the shadow run dir itself), not the target — chmod-ing `shadowStaged`/`shadowDecisions` directly (as #1171's tests do) exercises the readdir/readFileSync failure, not this stat/lstat gate.
