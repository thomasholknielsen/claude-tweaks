# 1673: archive-merged.js: auto-close a stale interrupted run using shipped-unclosed evidence

Surface: backend

## Overview

Extend `reconcile`'s archive pass so a stale `interrupted` run meeting the shipped-unclosed evidence bar (#1672 provides the torn-down-worktree fallback evidence path) with no owning session is auto-closed the same way a manual `close-run` closes it — eliminating the need for a human to notice and run `close-run` by hand on a run that's been sitting `interrupted` for days while accumulating fallback-attributed events.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- Not building the shipped-unclosed evidence path itself — that's #1672, which this record is blocked by.
- Not changing `hasMaterializeCommit`'s unbounded git-log range — that's #1674, covering different repro steps.
- Not changing how fallback-attributed events get attributed to the wrong run in the first place — #1402/#607's territory.

## Prerequisites

| Spec | Title | Status |
|------|-------|--------|
| #1672 | run-integrity.js: fallback evidence when deriveBranch can't resolve a torn-down worktree | ready |

## Current State

- `plugin/bin/lib/reconcile/archive-merged.js` — `archiveRunDir`/`archiveMerged` never treats an `interrupted` run with no owning session as closeable on its own; `archived: 0` every time for this shape.
- `plugin/bin/lib/hooks/close-run-state.js` — `closeRunState` is the mechanism manual `close-run` already uses, including its `close-without-wrapup` event and un-archived-`work/` advisory; the same `foreignOwner`/session-recency logic already decides whether a run has "no owning session."
- `plugin/bin/lib/hooks/context.js` — fallback-attributed events (`session-end`, `skill_invoked`, `gate-denial`, `worktree-staleness`) land in a stale run's `events.jsonl` under `attribution: fallback`, advancing its `updatedAt` and making a naive recency check see it as active.

## Deliverables

- [ ] Extend `archiveRunDir`/`archiveMerged` with a new auto-close criterion: a run is `interrupted`, has no owning session (reuse `close-run-state.js`'s existing `foreignOwner` check, inverted), and meets the shipped-unclosed evidence bar (via #1672's extended `checkRunIntegrity`).
- [ ] When the criterion matches, call `closeRunState` — the identical function manual `close-run` uses — so an automated close is indistinguishable in the ledger from a manual one (same `close-without-wrapup` event, same un-archived-`work/` advisory).
- [ ] `format-summary.js`'s `archived: N` count includes these auto-closed runs.
- [ ] Ensure the "no owning session" check does not rely on `updatedAt` alone — exclude fallback-attributed events (`attribution: fallback`) from whatever recency signal the check uses, so a stale run that only accumulated other sessions' fallback events is still recognized as abandoned.
- [ ] Add test coverage for: a torn-down, shipped, no-owning-session run (auto-closes), a run with a live owning session (not closed), and a run whose only recent events are fallback-attributed (still recognized as abandoned).

## Acceptance Criteria

1. A stale `interrupted` run meeting the shipped-unclosed evidence bar, with no owning session, is auto-closed by `reconcile` and counted in `archived: N`.
2. A run with a live owning session is never auto-closed by this criterion, regardless of evidence bar.
3. Fallback-attributed events landing in a stale run's `events.jsonl` no longer prevent that run from being recognized as closeable.
4. `npm test` passes, including new `archive-merged`/`reconcile` coverage for the three cases above.

## Technical Approach

Add a new branch to `archiveMerged`'s per-run-dir loop: after the existing `move-failed`/orphan checks, check `status === 'interrupted'` + no live owning session (reuse/invert `close-run-state.js`'s `foreignOwner` check, sourcing its recency read from non-fallback-attributed events only) + the shipped-unclosed evidence bar from #1672's extended `checkRunIntegrity`. On match, call `closeRunState` directly rather than re-implementing its logic.

### Key Files

- `plugin/bin/lib/reconcile/archive-merged.js` — `archiveRunDir`/`archiveMerged`: new stale-shipped-unclosed auto-close criterion
- `plugin/bin/lib/hooks/close-run-state.js` — reused as-is; read its `foreignOwner`/session-recency logic rather than reinventing it
- `plugin/bin/lib/reconcile/format-summary.js` — `archived: N` count: include auto-closed runs from this criterion

## Gotchas

- False-positive auto-close (closing a run a session is about to resume) is worse than today's status quo of a manual `close-run` — reuse `close-run-state.js`'s existing conservative ownership logic rather than inventing a new staleness window.
- Blocked by #1672, which provides the shipped-unclosed evidence path for a torn-down worktree — this criterion has nothing to check without it.
- Related: #1613 (open, not yet `ready`) proposes escalation paths for `archiveMerged`'s *other* skip reasons (`no-worktree`, `no-branch`, etc.) — a broader, separate concern from this deliverable's narrow new criterion. Coordinate rather than duplicate if #1613 is later specified.
