# 1219: Don't use AskUserQuestion to narrate waiting on background dispatches

## Current State

Nothing in `CLAUDE.md`, `docs/donts.md`, or any pipeline skill's prose currently tells an executing
agent that waiting on a background/async subagent dispatch is not a decision point. Observed during
a live `/claude-tweaks:flow` run (spec-343-900, subagent-driven-development execution of record #900):
the executing agent repeatedly called `AskUserQuestion` with a single-option "Acknowledged
(Recommended)" purely to narrate "waiting for background agent X" between implementer/reviewer
dispatches, many times in a row, with no real decision for the user to make. This directly undermines
`auto` mode's own hands-off contract (`flow/SKILL.md`: auto "silences ... all path-selection prompts
mid-pipeline") and created significant interruption/attention burden during what should have been a
hands-off run. Nothing in `flow/SKILL.md` or `subagent-driven-development`'s own guidance instructed
this pattern — it was the executing agent's own judgment error, and the `AskUserQuestion` tool's own
description already states a question needs at least two genuinely distinct choices, which "acknowledge
that I'm waiting" never has.

## Deliverables

- Add a rule to `docs/donts.md` (rule + brief why, matching that file's existing format) stating:
  waiting on a background/async agent dispatch (Agent tool, Task tool, or any harness-notified
  async work) is never itself a decision point and must never trigger `AskUserQuestion` — a plain
  narrated status line, or no output at all, is correct. The harness's own task-notification
  mechanism already surfaces completion asynchronously, so there is nothing to "keep the user
  informed" about that isn't already handled by that notification.
- Cross-reference or fold the same guidance into `flow/SKILL.md`'s auto-mode-contract citation, or
  `_shared/auto-mode-contract.md` itself, if it is judged to belong there instead of (or in addition
  to) `docs/donts.md` — evaluate at spec time which home fits best; don't duplicate the rule in both
  places.

## Acceptance Criteria

- A rule exists (in `docs/donts.md` and/or `_shared/auto-mode-contract.md`) explicitly stating that
  waiting on a background/async dispatch never justifies an `AskUserQuestion` call.
- The rule names its own why (the auto-mode hands-off contract, and `AskUserQuestion`'s own
  two-distinct-options requirement) so a future agent reading it understands when it applies.
- `npm test` passes (any prose-conformance test that would need updating for the new rule text is
  updated, not exempted).
