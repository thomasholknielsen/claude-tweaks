# 1216: escalate-residue.js: document the deliberate minimal-label filing posture in its header comment

Surface: backend

## Current State

`plugin/bin/lib/reconcile/escalate-residue.js` (added by #644) files a GitHub issue with `--label bug` only when a `move-failed`/`removal-failed` path crosses `RESIDUE_ESCALATE_THRESHOLD` consecutive failures. #1216 asked whether that minimal label set is a gap (option (b): expand the origin enum with a `by:reconcile` value and file born-`ready` with a hard-coded risk/size heuristic) or a deliberate posture (option (a): keep it plain).

**The decision is made (2026-08-29, via `/claude-tweaks:specify #1216` → brainstorming): option (a) refined — the posture is correct and stays.** Evidence, with the pickup mechanism named: the enrichment trigger is `/specify next` — the headless shaping unit `/claude-tweaks:specify` ships as a scheduled-Routine template (its own `## Routine Configuration` section, #967), not a manual browse; the `shaped:headless` provenance labels on the shaped records prove headless firings did the work. Of the 13 issues the module has filed (#1282–#1290, #1341, #1446, #1447, #1649), all 13 are accounted for: nine flowed shaping → `/backlog` grants (`auto:build`+`auto:merge`) → autonomous build → closed; #1446/#1447 are shaped and `ready` in the worklist; #1290 is granted and `bot:in-progress`; #1649 (filed 2026-08-25) is the only one not yet picked up, awaiting a firing — none stalled. A plain open issue IS a backlog-stage record (backlog = absence of stage labels, `_shared/work-record.md`), so minimal filing already enters the pipeline. The architectural reason: `risk:*`/`size:*` are content judgments, and reconcile runs in no-LLM contexts (session-start in-process, `bin/hooks.js reconcile` CLI) — moving scoring there would replace the working mechanical-writer → LLM-enrichment path with a worse one, at the cost of an expand-contract change to the closed origin enum. Latency posture, made explicit: "escalation" here means durable visibility plus an eventual autonomous fix at routine cadence — not paging; the module's own header already names `/tidy` sweeps and humans reading `reconcile`'s JSON as the backstop, and that is the accepted service level for this failure class.

What remains: nothing in the module's header records this reasoning, so a future reviewer (or health sweep) would re-flag the "missing" labels — exactly what #1216's own option-(a) acceptance criterion anticipated.

## Original request

escalate-residue.js's filed issues carry no work-record labels — invisible to /backlog automation (open question)

Origin: code review finding during the #644 rescue-rebase PR (bin/lib/reconcile/escalate-residue.js)

## Current State

`escalate-residue.js` (added by #644's reconcile-residue-escalation fix) files a plain GitHub issue — `--label bug` only — when a `move-failed`/`removal-failed` path crosses `RESIDUE_ESCALATE_THRESHOLD` consecutive failures. It carries none of this project's internal work-record taxonomy (`by:*`, `type:*`, `risk:*`, `size:*`, `ready`), so it never appears in `/backlog`'s or `/dispatch`'s `--label ready`-filtered queries — a human has to notice it by browsing issues directly.

This might be entirely correct as designed: `/claude-tweaks:feedback`'s own filing convention (`_shared/work-record.md`'s `/feedback` row) is the same shape on purpose — `bug`/`enhancement` only, explicitly excluding "every other label in this repository's own internal automation taxonomy." A plain, externally-visible bug report that a human triages manually is a defensible posture for a system that's escalating a stuck path in the reconciler's own infra, not asking the pipeline to autonomously go fix itself.

But it could equally be argued the other way: `/code-health`'s own filing convention (`skills/code-health/filing.md`) is "born-`ready`" with the full `by:{self}`/`risk:*`/`size:*`/`ready` set, specifically so an agent-sized, spec-shaped finding enters the authorization gate's worklist without a human having to hand-triage it into the pipeline. Reconcile's escalated residue could reasonably be filed the same way.

## Open question

Should `escalate-residue.js`'s filed issues:
(a) stay plain-bug-report-only (mirror `/feedback`'s posture — a human always triages), or
(b) gain the full work-record label set (mirror `/code-health`'s posture — auto-buildable, needs a new `by:reconcile`-style origin value added to the closed 6-member origin enum in `_shared/work-record.md`, plus a default risk/size heuristic reconcile has no existing signal for)?

This is a real product/taxonomy decision (adding a new origin-axis member is itself an expand-contract change per CLAUDE.md's own conventions), not a mechanical fix — hence filing rather than fixing inline in the #644 PR.

## Acceptance Criteria

- A decision is made and recorded on (a) vs (b) above (or a third option).
- If (b): `by:reconcile` (or equivalent) is added to `_shared/work-record.md`'s Origin row, `escalate-residue.js`'s `escalateResidue()` is updated to file with the full label set, and its own tests updated to assert the new labels.
- If (a): this issue is closed as working-as-intended, with a one-line note in `escalate-residue.js`'s header comment stating the posture was a deliberate choice (so a future reviewer doesn't re-flag it).
