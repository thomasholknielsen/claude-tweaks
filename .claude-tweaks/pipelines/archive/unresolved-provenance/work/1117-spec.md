# 1117: Ad-hoc run dirs #500's Friction lens depends on get silently auto-archived by the pre-existing 24h orphan-mint sweep

Surface: backend

Origin: spec #500 review (3c: Error Handling)

Defer-reason: needs-human-decision

## Current State

#500's chosen implementation (candidate 2, commit 5542f6a4) mints an ad-hoc run dir via `runDirResolve.resolve({..., standalone: 'adhoc'})`, which — like every standalone mint (`plugin/bin/lib/hooks/run-dir-resolve.js`'s standalone branch) — only ever creates `decisions.md` + `staged/`, never `config.yml` (that's written later, only by `/flow`'s Manifesto).

The pre-existing reconcile sweep `archiveMerged` (`plugin/bin/lib/reconcile/archive-merged.js`) — part of `ALL_CHECKS`/`BACKGROUND_CHECKS`, run automatically by every SessionStart's detached `reconcile-background` child and by `/tidy` — treats *any* run dir with no `config.yml` and a directory mtime older than `ORPHAN_MINT_TTL_MS` (24h, `isOrphanedMint`) as an abandoned `/flow`/`/dispatch` mint and silently `fs.renameSync`s it straight into `archive/` (`archiveOrphanedMint`) — no state/console/PR check at all, since that check runs *before* the branch that would otherwise protect a live run.

Once archived, `iterRunDirsWithState`'s `isArchivedRunId` filter makes the dir permanently invisible to `findRunsByWorktreePath`/`bin/friction-events.js` — the new read side #500 added for the Friction lens.

Net effect: an ad-hoc worktree dev session whose worktree goes untouched (no new hook write bumping the dir's mtime) for more than ~24h before `/claude-tweaks:wrap-up` finally runs loses its entire friction record silently, with no error or log — reopening exactly the blind spot #500 was filed to close, for the realistic case of a delayed wrap-up. This was independently verified by tracing the actual code path (`run-dir-resolve.js`'s standalone branch, `archive-merged.js`'s `isOrphanedMint`/`archiveMerged`, `reconcile/index.js`'s `ALL_CHECKS`, `bin/hooks.js`'s `BACKGROUND_CHECKS`, and `context.js`'s `iterRunDirsWithState`/`isArchivedRunId`), not merely reported by a single reviewer agent.

A visible symptom in the meantime: until the sweep fires, the ad-hoc dir's `run-state.json` stays `active`/`interrupted` forever (nothing ever stamps it `clean`), so it surfaces in SessionStart's "unfinished pipeline run(s) detected" nag for every subsequent session anywhere in the project — until the 24h sweep silently removes it, at which point the nag stops because the data was destroyed, not because anything was resolved.

## Deliverables

Give ad-hoc-standalone run dirs (the `-adhoc-standalone` suffix minted by `stampAdHocRunDir`) an explicit, deliberate lifecycle answer instead of falling through the generic `isOrphanedMint` 24h sweep built for a different case (abandoned `/flow`/`/dispatch` pre-Manifesto mints). This needs a design decision, not a mechanical patch — options include (pick one, or a better one):

1. Exempt `-adhoc-standalone`-suffixed dirs from `isOrphanedMint` entirely (they're deliberately standalone-forever by design, not "abandoned before adoption") and give them their own, much longer or absent TTL, swept only once genuinely superseded (session ends / wrap-up adopts or archives them explicitly).
2. Have `/claude-tweaks:wrap-up`'s own reflect pass (or `session-end.js`) explicitly archive/consume the ad-hoc dir when it runs, so it never needs to survive unbounded — and have the reconcile sweep only ever touch dirs stamped `interrupted`/no activity past a shorter, ad-hoc-appropriate window that a real dev session wouldn't hit.
3. Some combination — e.g. a distinct marker file `isOrphanedMint` (or a sibling check) recognizes as "this is a deliberately-long-lived standalone dir, not an abandoned mint."

Whichever is chosen: update `docs/hooks.md`'s run-dir lifecycle/ownership contract and `plugin/skills/reflect/full-mode.md`'s Friction Lens section to document it, and add regression coverage proving an ad-hoc run dir survives `archiveMerged`/`isOrphanedMint` across the relevant TTL boundary.

## Acceptance Criteria

- An ad-hoc-standalone run dir that has received no hook writes for >24h (simulating a multi-day dev session, or a same-day session with a delayed wrap-up) is NOT silently archived by `archiveMerged`/`isOrphanedMint` before `/claude-tweaks:wrap-up`'s reflect pass has a chance to read it.
- `bin/friction-events.js` (or the Friction lens's read path) still finds this dir's events after the reconcile sweep has run against it.
- Existing `/flow`/`/dispatch` abandoned-pre-Manifesto-mint archival behavior (the case `isOrphanedMint` was originally built for) is unaffected — its own tests stay green.
- `npm test` passes, including new coverage for this interaction.
- `docs/hooks.md` and `plugin/skills/reflect/full-mode.md`'s Friction Lens section document the chosen lifecycle.
