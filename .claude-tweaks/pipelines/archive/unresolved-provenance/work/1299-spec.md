# 1299: resolveRunArg's #280 fallback: a live pipelines/{id} shadow can still be adopted over an archived main-checkout twin under the same id

Defer-reason: genuinely-larger
Surface: backend

## Current State

Record #1183 (PR #1265) closed the `#280` `--run` fallback's twin-collision gap in one direction: a worktree-local `pipelines/archive/{id}` shadow is now correctly refused when a LIVE (non-archived) run exists under the same id at the main checkout (`plugin/bin/hooks.js`'s `resolveRunArg`, `mainLiveCandidate`/`twinExists`). The mirror direction was left open, confirmed live during that record's `/claude-tweaks:review` pass (probed against the shipped code): a worktree-local LIVE `pipelines/{id}` shadow is still adopted even when the main checkout holds that same run-id ARCHIVED at `pipelines/archive/{id}`. This is not a regression from #1183 — it is identical to the pre-#1183 basename-only behavior for this specific direction — but it is the same containment class the record otherwise closed, and #1183's own review deliberately deferred it rather than expanding that record's scope.

## Deliverables

- Extend `resolveRunArg`'s twin check so a live-shape candidate (`relParts[0] !== 'archive'`) is also checked against `mainRoot/.claude-tweaks/pipelines/archive/{runIdSegment}` — the mirror of the `mainLiveCandidate` check #1183 added for the archive-shape direction.
- A regression test proving the fix: a worktree-local LIVE `pipelines/{id}` shadow (initialized) is refused when the main checkout holds `pipelines/archive/{id}` (bare directory, matching the existing twin tests' isDirectory-only bar).

## Acceptance Criteria

- A worktree-local live `pipelines/{id}` shadow is refused via the `#280` fallback when the main checkout has that same id archived.
- Existing `#1183` coverage in `tests/hooks-run-arg-anchoring.test.js` still passes (no regression to the already-closed archive→live direction).

## Technical Approach

Mirror the existing `mainLiveCandidate` pattern (`plugin/bin/hooks.js`, `resolveRunArg`, search for `isArchiveShape`): add a `mainArchivedCandidate` computed when `inPipelines && !isArchiveShape`, pointing at `path.join(mainRoot, '.claude-tweaks', 'pipelines', 'archive', runIdSegment)`, and OR it into `twinExists` alongside `mainCandidate` and `mainLiveCandidate`.

### Key Files

- `plugin/bin/hooks.js` — `resolveRunArg`'s twin-check block (search `mainLiveCandidate`/`twinExists`)
- `tests/hooks-run-arg-anchoring.test.js` — mirror the existing `#1183 fix-wave: reject — a worktree-local archive/{id} shadow is refused when a LIVE ... run dir exists` test, inverted

## Gotchas

- Keep the fix scoped to this one additional check — do not re-open or re-derive the rest of `resolveRunArg`'s containment logic, which is otherwise settled and reviewed.
