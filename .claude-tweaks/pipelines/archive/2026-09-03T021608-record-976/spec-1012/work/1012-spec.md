# 1012: hooks.js mutating verbs: unknown-flag rejection, unambiguous-only implicit run resolution, composite ownership guard

Surface: backend

## Overview

Harden the five mutating run-state verbs in `plugin/bin/hooks.js` (`close-run`, `record-worktree`, `record-pr`, `spec-status`, `teardown-run`) against sibling-agent stomps: unknown-flag rejection, an unambiguous-only implicit fallback, and a write-time ownership guard built on `classifyOwnership`.

## Original incidents (preserved)

- A Task-tool build/review subagent working on #860 omitted `--run` on one `record-worktree`/`close-run` call; the CLI fell through to its "newest non-terminal run" fallback and silently overwrote a LIVE sibling session's `run-state.json`.
- #965: a mistyped `close-run --help` fell through to the same fallback and overwrote spec-315's run-state three separate times, from three different sibling worktrees, all sharing the parent session's `CLAUDE_CODE_SESSION_ID`.

## Current State

- `plugin/bin/hooks.js` — `resolveRunArg(args, cwd, env)` (shared by all five verbs): looks only for `--run`; anything else silently falls through to `ctxLib.resolveRunDir(cwd, env)` — called WITHOUT a sessionId third argument. `record-worktree`, `record-pr`, and `spec-status` have no ownership check at all on the implicit path.
- `plugin/bin/lib/hooks/close-run-state.js` — `closeRunState(runDir, { explicit, sessionId })`: refuses an implicit close only when `prev.sessionId !== sessionId` — defeated by the shared session id.
- `plugin/bin/lib/hooks/context.js` — `classifyOwnership` (shipped by #1098, merged): composite identity verdict `'mine' | 'foreign' | 'indeterminate'`.

## Deliverables

- [ ] Known-flag declaration per verb at the `resolveRunArg` seam: any `--*` argument not in the verb's declared set prints that verb's usage and exits without reading or writing any run state. Declared sets: `close-run`: `--run`; `record-worktree`: `--run`; `record-pr`: `--run`; `spec-status`: `--run`, `--spec`, `--status`, `--phase`, `--now`; `teardown-run`: `--run`, `--merged`, `--abandoned`.
- [ ] Implicit resolution (no `--run`) for the five mutating verbs replaced with the unambiguous-only order: (1) `PIPELINE_RUN_DIR` env — no longer exempt from the write-time guard; (2) cwd-binding reverse lookup via `findRunByWorktreePath`; (3) after excluding candidates whose `classifyOwnership` verdict is `foreign`, exactly one candidate remains → act on it; (4) otherwise refuse, listing every non-terminal candidate, foreign ones annotated.
- [ ] `closeRunState`'s `foreignOwner` predicate upgraded from raw session-id comparison to `classifyOwnership`. Signature: `closeRunState(runDir, { explicit, callerIdentity })` with `callerIdentity = { sessionId, cwd }`.
- [ ] `record-worktree`, `record-pr`, and `spec-status` refuse an implicit write when the resolved run's `classifyOwnership` verdict is `foreign`.
- [ ] Named regression test, fixture pinned exactly: four non-terminal run dirs; callers A, B, C each cwd'd in their own worktree with their own run bound to it; run D bound to a fourth worktree whose agent is absent; all four runs record the same `sessionId`.
- [ ] Update `tests/hooks-dispatcher.test.js`'s existing no-`--run` cases to the new semantics, clearing `PIPELINE_RUN_DIR` in every spawn env.

## Acceptance Criteria

1. Each of the five verbs, given any undeclared `--*` flag, prints usage and performs zero reads/writes of any `run-state.json`.
2. Bare `close-run` with exactly one non-terminal candidate remaining after the foreign-exclusion filter acts on it; with two or more surviving candidates, or with zero survivors, it refuses.
3. A caller whose cwd is inside worktree A can never implicitly resolve, close, or overwrite a run bound to worktree B, even with identical `CLAUDE_CODE_SESSION_ID`.
4. Explicit `--run` on a foreign run still proceeds, printing the existing advisory.
5. `record-worktree --run <dir>` behaves byte-identically to today.
6. Bare `record-worktree` (no `--run`) with two or more non-terminal runs present, or with its only candidate classified `foreign`, refuses without writing.
7. Full `npm test` green; reverting the hooks.js/close-run-state.js changes (keeping the new tests) makes the new tests fail.

## Technical Approach

Extend `resolveRunArg` to take the verb's known-flag list and return an `unknownFlag` field the caller turns into the usage line; thread a `callerIdentity = { sessionId: process.env.CLAUDE_CODE_SESSION_ID, cwd: process.cwd() }` object into the implicit-resolution path and the write guards. The unambiguous-only candidate scan reuses `iterRunDirsWithState` (newest-first) exactly as `resolveRun` does.

### Data / API Surface

- `resolveRunArg(args, cwd, env, { knownFlags, callerIdentity })` → `{ runDir, invalidRunArg, unknownFlag, rest, explicit, candidates }`.
- Refusal message shape: `claude-tweaks: multiple candidate runs — pass --run explicitly:` when 2+ survive the filter, `claude-tweaks: the only candidate run(s) are recorded by another session/worktree — pass --run explicitly to act on one:` when zero survive — followed by one `node "<path>/bin/hooks.js" <verb> --run "<dir>"` line per non-terminal candidate.

### Key Files

- `plugin/bin/hooks.js` — `resolveRunArg` + the five verb handlers
- `plugin/bin/lib/hooks/close-run-state.js` — guard upgrade
- `plugin/bin/lib/hooks/context.js` — read-only consumption of `classifyOwnership`/`findRunByWorktreePath`
- `tests/hooks-dispatcher.test.js` — updated cases + the named regression test

## Gotchas

- The shared session id means the old guard *passes* for siblings — any test asserting foreign-refusal must use identical session ids across callers, plus a distinct-id case to prove the old arm still works.
- `spec-status`'s `--run` names the multi-spec PARENT run dir, never a per-spec subdirectory.
- `teardown-run` reaches `closeRunState` via `teardown-run.js` Step 1 — verify both entry points get the upgraded guard.
- A refusal must exit with output naming what was refused and why — never print nothing and exit 0.
- #953 and #761 (open) also touch `plugin/bin/hooks.js`; #457 touches `tests/hooks-dispatcher.test.js` — check for merge overlap before building.
