# 1099: pre-tool-use E-checks + resolveRun attribution: classify same-session sibling worktrees as foreign

Surface: backend

## Overview

Enforcement-layer half of the #965 run-state ownership hardening (parent record has the full rationale): the two inline `owner !== caller` session-id comparisons in `plugin/bin/lib/hooks/pre-tool-use.js`, and `resolveRun`'s session-scoped `attribution: 'session'` path in `plugin/bin/lib/hooks/context.js`, all assume session id ≡ actor. Because `CLAUDE_CODE_SESSION_ID` is shared across all subagents of a session (measured 2026-08-20, #965), a sibling agent in its own worktree is misclassified as the run's own session: the E-checks take the same-session branch (deny) instead of the foreign branch (warn/allow + event), and `resolveRun` confidently returns a sibling's run as the caller's own. These fail toward deny/warn rather than corruption — lower stakes than the mutating verbs — but they are the same broken equivalence and complete the ownership contract.

## Current State

- `plugin/bin/lib/hooks/pre-tool-use.js` — two sites compare `state.sessionId` against the hook payload's `ctx.input.session_id`. Teardown path: `if (owner && caller && owner !== caller)` → foreign branch (allow + `wd-foreign-teardown` event + warning); everything else — same-session, unowned target, or missing identity on either side — falls through to one deny. Commit path: the same `owner && caller && owner !== caller` guard → foreign branch (allow + `wd-foreign-session` event + systemMessage); everything else, missing-identity cases included, falls through to `wd-deny`. The teardown site classifies the **target** run (`hit.state`, found by worktree path); the commit site classifies the caller's **own resolved** run (`ctx.runState`) — pass each site its own `state` object.
- `plugin/bin/lib/hooks/context.js` — `resolveRun(cwd, env, sessionId)`: with a known session id, returns the first run whose `state.sessionId === me` as `attribution: 'session'`; under shared ids the first such run may be a sibling's. `classifyOwnership` (shipped by #1098, merged): verify the shipped signature and verdict strings against that record's Data / API Surface table at build start.
- Tests: the pinning surface for existing behavior is `tests/hooks-gate-coverage.test.js` plus every suite exercising `resolveRun`.

## Deliverables

- [ ] Both `pre-tool-use.js` comparison sites decide foreign-vs-own via `classifyOwnership({ sessionId: ctx.input.session_id, cwd: ctx.cwd }, state)` instead of raw id equality: verdict `foreign` takes the existing foreign branch, `mine` the existing same-session branch, `indeterminate` preserves each site's current missing-identity behavior (teardown path: deny; commit path: fall through to `wd-deny`) — outcome semantics per classification unchanged, only the classifier swapped.
- [ ] `resolveRun`'s session-scoped loop skips a run whose `classifyOwnership` verdict against the caller is `foreign` (sibling's bound run) instead of returning it as `attribution: 'session'`. **Only `foreign` skips**: an `indeterminate` verdict keeps today's behavior and is still returned as `attribution: 'session'`.
- [ ] Pinning tests: (a) existing single-session scenarios in the hooks suites pass unchanged; (b) new cases: same session id + caller cwd in worktree A vs a run bound to worktree B → teardown path classifies foreign, commit path classifies foreign, `resolveRun` skips the sibling run.

## Acceptance Criteria

1. A sibling agent (identical session id, own worktree) tearing down or committing against another sibling's bound run takes the foreign branch at both `pre-tool-use.js` sites. The dual case is asserted alongside it: the run's own session with cwd inside the recorded worktree still classifies `mine`.
2. `resolveRun` with a session id never returns `attribution: 'session'` for a run whose recorded worktree is a different live worktree than the caller's cwd.
3. Every existing `tests/hooks-gate-coverage.test.js` and hooks-suite assertion passes without modification.
4. Reverting the pre-tool-use/context changes (keeping the new tests) makes the new tests fail.
5. Full `npm test` green.

## Technical Approach

Both sites already have `ctx.cwd`/`ctx.input` in scope — construct the caller identity once per check, call the predicate, and map its three verdicts onto each site's existing branches. In `resolveRun`, apply the predicate only inside the `owner === me` arm.

## Gotchas

- The shared session id means the old guard *passes* for siblings — any test asserting foreign-refusal must use identical session ids across callers.
- `indeterminate` must not accidentally take the foreign (allow) branch on the teardown path.
