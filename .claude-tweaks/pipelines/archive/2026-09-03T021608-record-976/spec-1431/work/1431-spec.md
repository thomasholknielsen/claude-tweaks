# 1431: subagent-stop.js contract-violation events cross-contaminate across concurrent pipeline runs

Surface: backend

## Current State

During #1108's review, `events.jsonl` in that run's pipeline directory contained three `"type":"contract-violation"` entries whose `firstLine` content is unrelated to #1108's own docs-only scope, tracing to a concurrent, unrelated sibling run. Root cause: `plugin/bin/lib/hooks/subagent-stop.js`'s `run(ctx)` appends this event using the raw `ctx.runDir`, which `context.js`'s `resolveRun` can set via a documented `attribution: 'fallback'` guess. `post-tool-use.js` was already hardened against the identical failure mode for the sibling `commit` event type — scoped to `ctx.ownedRun` instead of `ctx.runDir`, passing `ownedRun.attribution` through to `appendEvent`'s fourth argument — but `subagent-stop.js` never received that same hardening.

A grep of every `appendEvent(` call site under `plugin/bin/lib/hooks/*.js` additionally found several `ctx.runDir`-gated calls in `pre-tool-use.js` (lines ~877, 881, 1137, 1157, 1163, 1174) not yet judged against this same distinction.

## Deliverables

- [ ] Apply `post-tool-use.js`'s `ctx.ownedRun`-scoping + attribution-tagging pattern to `subagent-stop.js`'s `contract-violation` event append
- [ ] Audit the other `appendEvent` call sites in `bin/lib/hooks/` found during this pass (`pre-tool-use.js`, the line numbers above — re-derive current line numbers at build time since #976/#1099 in this same bundle also touch this file) for the same unhardened `ctx.runDir` (vs. `ctx.ownedRun`) usage, and harden each one that turns out to be an event-attribution write rather than a session-agnostic worktree-bookkeeping comparison

## Acceptance Criteria

1. A `SubagentStop` hook firing in a session with no confirmed run ownership (fallback-attributed `ctx.runDir`) either tags the appended event as fallback-attributed or does not append it to a run directory it does not own, matching `post-tool-use.js`'s existing `commit`-event hardening
2. Each `pre-tool-use.js` call site named in Deliverables is individually resolved — either hardened to `ctx.ownedRun` with attribution tagging, or left as `ctx.runDir` with a one-line comment recording why that call is a session-agnostic worktree-bookkeeping comparison rather than an event-attribution write
3. `node --test tests/hooks-log-modules.test.js` continues to pass, extended with a case asserting that a fallback-attributed run either doesn't receive the `contract-violation` event or receives it tagged `attribution: 'fallback'`

## Technical Approach

In `subagent-stop.js`'s `run(ctx)`, replace the `if (!ctx.runDir) return {};` guard and the bare `ctxLib.appendEvent(ctx.runDir, 'contract-violation', {...})` call with the same shape `post-tool-use.js`'s commit-event handler already uses:

```js
const ownedRun = ctx.ownedRun || {};
if (!ownedRun.dir) return {};
...
ctxLib.appendEvent(ownedRun.dir, 'contract-violation', { firstLine }, ownedRun.attribution);
```

No plumbing changes are needed elsewhere: `bin/hooks.js`'s `runHook` already resolves and passes `ownedRun` into every hook module's `ctx`.

For the audit deliverable, judge each `pre-tool-use.js` call site on whether it's an event-attribution log write (harden it) or a check that legitimately needs the session-agnostic "run this worktree is currently assigned to" (`ctx.runDir`) rather than "a run this session owns" (`ctx.ownedRun`).

### Key Files

- `plugin/bin/lib/hooks/subagent-stop.js` — swap the `ctx.runDir` gate and unattributed `appendEvent` call for `ctx.ownedRun`-scoped gate + attribution-tagged `appendEvent`
- `plugin/bin/lib/hooks/post-tool-use.js` — reference pattern only; no change expected
- `plugin/bin/lib/hooks/pre-tool-use.js` — audit target
- `tests/hooks-log-modules.test.js` — existing `subagent-stop` coverage; extend with a fallback-attribution case

## Gotchas

- `post-tool-use.js`'s hardening pattern passes `ownedRun.attribution` as `appendEvent`'s fourth argument; `context.js`'s `appendEvent` only stamps an `attribution` field when that value is literally `'fallback'` — passing it unconditionally is safe.
- `subagent-stop.js` is "best-effort by design" — the fix must stay a no-op-on-uncertainty change (drop or tag, never block).
- Not every `ctx.runDir` usage in `pre-tool-use.js` is a bug — some compare against "the run this worktree is currently assigned to" (session-agnostic), a different question from "does this session own a run to write to." Each site needs its own read.
- Build this last within the bundle (after #976 and #1099, which also touch `pre-tool-use.js`) so the audit's line numbers/context are current against this bundle's own changes, not stale pre-bundle numbers.
