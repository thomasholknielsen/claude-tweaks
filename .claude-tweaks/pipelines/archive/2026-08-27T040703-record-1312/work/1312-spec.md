# 1312: fleet.md's Grants issued counter doesn't distinguish pending vs matured machine grants

Surface: infra

## Current State

`plugin/skills/routine/fleet.md`'s "Grants issued" counter row (confirmed live at line 207) reads:

```
| Grants issued | {machine} machine / {human} human | in-window `auto:build`/`auto:merge` label events; machine identified by the `<!-- grant-mode-audit: ... -->` comment marker (#269), human by its absence | grants counted from audit comments cannot see pre-feature history; a human grant's timestamp comes from the label-add event, which GitHub's timeline may paginate |
```

The underlying counter logic (`plugin/bin/lib/issues/fleet-counters.js`, confirmed at `isMachineGrant`/`GRANT_AUDIT_RE`) counts a grant as "machine" the moment any comment carrying the `<!-- grant-mode-audit: ... -->` marker exists — it does not distinguish whether that grant is still inside its post-#309 veto window (pending) or has passed it (matured). Surfaced while implementing #309's veto-window maturation: the check already counts pending-marker comments correctly (i.e. the counting mechanism itself is fine), but the doc row's narrative text doesn't mention that "machine" grants shown by this counter may include ones not yet matured.

## Deliverables

- Update `routine/fleet.md`'s "Grants issued" row (~line 207) Source or Blind spot column text to note that the machine count includes grants still inside their post-#309 veto window (pending) alongside fully matured ones — display wording only, no change to `isMachineGrant`/`GRANT_AUDIT_RE` or any other counting logic.

## Acceptance Criteria

- `routine/fleet.md`'s "Grants issued" row text distinguishes pending vs. matured machine grants (or explicitly states the count doesn't distinguish them, if that's the clearer phrasing) — a human reading the counter's output understands what "{machine}" actually represents.
- No change to `plugin/bin/lib/issues/fleet-counters.js` or any other counting logic — this is a documentation-only fix.

## Technical Approach

A one-line prose edit to `routine/fleet.md`'s existing table row (~line 207) — either the Source column (naming that the count includes pending grants) or the Blind spot column (naming that pending vs. matured isn't distinguished in the displayed number), consistent with the table's existing "Counter honesty is structural" convention (each cell's Source and Blind spot columns already render in the output, per the file's own note just below the table). No code change.
