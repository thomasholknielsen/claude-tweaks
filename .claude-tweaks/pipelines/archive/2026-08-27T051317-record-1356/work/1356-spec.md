# 1356: PR-early run lifecycle can silently no-op with zero decisions.md trail

Origin: record #1268 review/wrap-up (near-miss found during resume)

## Current State

`build/worktree-setup.md` Step 6 invokes `_shared/pr-early-run-lifecycle.md`
once per run, immediately after the materialize commit, to push the branch
and open a draft PR (`pr-first` projects). That file's push-failure path has a
**mandatory** log line (`AUTO {time} — PR-early run lifecycle: push of
{branch} to origin FAILED ...`) specifically because #838 found a run
(`2026-08-17T164729-record-81`) whose `decisions.md` carried no trail at all
for a missing `pr` object.

Record #1268's own run (`2026-08-24T043213-record-1268`, `worktree-record-1268`)
hit the same symptom via a different path: when its `/flow review,polish,wrap-up`
call resumed after a prior `/flow build,test` call, no PR existed for the
branch and `git ls-remote` showed the branch itself had never been pushed to
`origin` — yet `decisions.md` held only `/dispatch` and `/build` entries, with
no push attempt, no `gh pr create` attempt, and no FAILED-push degrade line.
The mandatory log line only covers the case where Step 6 *ran and failed* —
there is no equivalent trail for Step 6 silently not running (or running and
succeeding with nothing recorded) at all. The gap self-healed via
`pr-early-run-lifecycle.md`'s own "next phase's own phase-exit push naturally
retries" design (`review`'s phase-exit pushed the branch and created the PR
late), but a human or agent auditing `decisions.md` mid-run would have no way
to distinguish "Step 6 hasn't run yet" from "Step 6 ran and this is fine" from
"Step 6 silently skipped."

## Deliverables

- [ ] Add a mandatory success-path log line to `_shared/pr-early-run-lifecycle.md`'s
      Step 2 (push) and Step 3 (PR creation) — e.g. `AUTO {time} — PR-early run
      lifecycle: pushed {branch}, opened PR #{n}.` — mirroring the existing
      FAILED-push line's "mandatory, not optional" framing, so every run-start
      invocation of this file leaves a trail regardless of outcome.
- [ ] Confirm `build/worktree-setup.md` Step 6 actually reaches this file on
      every code path that creates a worktree + materialize commit (the
      original gap here may be a caller-side skip rather than a lifecycle-file
      bug — both need checking).

## Acceptance Criteria

Every `pr-first` run's `decisions.md` carries at least one `PR-early run
lifecycle` log line after Step 6 executes, on both the success and failure
paths — never a run that reaches review/wrap-up with a missing `pr` stamp and
zero explanatory trail in `decisions.md`.
