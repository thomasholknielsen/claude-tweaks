# 1273: Wire the /tidy digest sweep into tidy's dispatch/scope/Action-Vocabulary machinery

**Related:** #1279

Origin: capture
Defer-reason: genuinely-larger

Wire the /tidy digest sweep into tidy's own dispatch/scope/Action-Vocabulary machinery — it currently exists only as a table row with no run actually invoking it.

## Current State

Record #1261 (materiality floor contract, digest, tidy sweep) added `plugin/skills/tidy/digest-sweep.md` (three procedures: bootstrap-race repair, cluster promotion, expiry) and a Step 5.6 row in `plugin/skills/tidy/SKILL.md`'s Scan Steps table. The final whole-branch review of that record found the sweep is not actually reachable from any real `/tidy` run:

- `digest-sweep.md`'s own header claims it runs "on an unscoped run, or `--scope=backlog`/`--scope=github`" but `SKILL.md`'s canonical Scope Selection table only maps `backlog`→Step 1 and `github`→Step 4.8 — no scope selects 5.6, and the table's own rule is "unknown scope name → stop."
- `tidy/scan-execution.md` (the canonical dispatch contract) enumerates the agent-backed steps as "Steps 1, 3, 4.5, 4.7, 4.8, and 5.5" — Step 5.6 is absent, and no agent owns dispatching it.
- `SKILL.md`'s Routine Configuration degrade list (~line 211) also omits 5.6.
- `SKILL.md`'s Action Vocabulary is a closed set of 13 named actions; Step 7 says "Execute each approved action per the Action Vocabulary table above." None of the sweep's real outputs (file a promoted record, merge-and-close a duplicate digest issue, post an expiry summary comment, close-and-rebootstrap at 100 comments with a pin move) map to any of the 13.
- `tidy/step-6-auto.md`'s aggressiveness-tier routing table has no row for any digest-sweep action, though every output is an outward-facing GitHub write that table would normally stage at every tier.
- `digest-sweep.md` instead routes its cluster-promotion proposal to `{run-dir}/staged/digest-promotion-{n}.md` (wrap-up's staged-patch shape), bypassing tidy's own Step 6 decision surface — a deliberate plan choice never reconciled with SKILL.md's own sentences describing that vocabulary as exhaustive.
- On `work-backend: github-issues`, the Expiry procedure defines no expiry marker (unlike its promotion marker `→ #{n}`) — an expired entry never leaves the active set, so the next sweep re-fires an expiry summary for the same entries forever. Only the `local-files` branch (physically moving lines to an `## Archived` section) actually removes an entry.
- Two smaller inconsistencies to fold in: (a) `digest-sweep.md`'s Cluster promotion procedure reads for a generic "no trailing `→ {id}` marker" but writes the GitHub-specific `→ #{n}` — internally inconsistent, and wrong on `local-files`; (b) `tidy/step-6-auto.md` already uses "Digest" for an unrelated >40-line report-shortening rule, and the new container/`[digest]` prefix/`digest` label now collide with that term in the same skill's vocabulary.

## Deliverables

- [ ] Add Step 5.6 to `tidy/SKILL.md`'s Scope Selection table with an appropriate `--scope=` value (or fold it into an existing scope) — a judgment call for whoever picks this up.
- [ ] Add Step 5.6 to `tidy/scan-execution.md`'s dispatch-agent list, naming (or creating) the agent that owns inlining `digest-sweep.md` and reading/writing the container.
- [ ] Add Step 5.6 to `SKILL.md`'s Routine Configuration degrade list.
- [ ] Either extend tidy's closed Action Vocabulary with the digest sweep's real actions (promote, merge-close-duplicate, expiry-summary, rollover-rebootstrap) plus matching `step-6-auto.md` tier rows, OR explicitly document in both `SKILL.md` and `digest-sweep.md` why the sweep's proposals bypass Step 6/7 via the `staged/` route instead — whichever is the smaller, more consistent change.
- [ ] Define a github-issues expiry marker in `digest-sweep.md`'s Expiry procedure so an expired entry actually leaves the active set.
- [ ] Fix the `→ #{n}` vs `→ {id}` marker-shape inconsistency in `digest-sweep.md` — generalize to `{id}`, with `#{n}` only as the github-issues instantiation — and update `tests/materiality-floor-conformance.test.js`, which pins the literal `→ #{n}`.
- [ ] Resolve the "Digest" naming collision between the new container/finding-prefix/label and `step-6-auto.md`'s existing >40-line-report-shortening "Digest" concept.

## Acceptance Criteria

1. An unscoped `/tidy` run (or whichever scope is chosen) actually dispatches Step 5.6 — traceable end-to-end from `SKILL.md`'s scope resolution through `scan-execution.md`'s agent list to `digest-sweep.md`'s procedures.
2. Every real output the digest sweep can produce maps to either a named Action Vocabulary entry with a `step-6-auto.md` tier row, or has an explicit, SKILL.md-stated exception explaining the `staged/` bypass — no orphaned output category.
3. A `github-issues` expiry marker exists and is stated in `digest-sweep.md`; re-running the sweep against an already-expired-and-summarized entry does not re-summarize it.
4. `digest-sweep.md` and `tests/materiality-floor-conformance.test.js` agree on the canonical marker shape.
5. `npm test` passes.

## Technical Approach

Filed by the final whole-branch review of spec #1261 — that record's own scope was contract creation + sweep procedures only; wiring the sweep into tidy's mature scan/dispatch/report/execute pipeline is a distinct unit of design work. It does not block #1261 (nothing routes to the digest yet, since adopters land in the separate #1262), but must not be silently dropped.
