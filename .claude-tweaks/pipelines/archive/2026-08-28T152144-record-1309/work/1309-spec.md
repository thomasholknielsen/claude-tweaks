# 1309: resolve-blockers.js: extend to expose per-blocker open state so dispatch's queue-pull-script.md can also drop its hand-rolled gh api graphql

Defer-reason: tangential
Surface: infra

## Current State

#1174 wired `bin/resolve-blockers.js` into `wrap-up/unblocked-records.md`'s `work-links: native` branch, replacing a hand-rolled `gh api graphql -f query="$(cat /tmp/...)"` block, and extended the CLI to accept a comma-joined number list so it stays a single batched call regardless of how many records it checks.

`plugin/skills/dispatch/queue-pull-script.md` has an identical hand-rolled `gh api graphql` block for the same `work-links: native` blocked-by check (found via #1174's own "sweep for other hand-rolled blocked-by GraphQL sites" deliverable), but its downstream consumer — `bin/lib/issues/record.js`'s `partitionByOpenNativeBlockers(candidates, repoData)` — needs the *raw* per-blocker GraphQL shape (`repoData['i'+n].blockedBy.nodes[].state`/`.number`), not `resolve-blockers.js`'s current parsed output (`{blockedBy: number[], openBlocker: boolean}`, which only exposes ALL blocker numbers and a single collapsed open/closed boolean — not which specific blockers are open). Dispatch's own "Blocked-exclusion report" needs to name the specific blocker id(s) that excluded a candidate, which the current CLI output can't supply.

`#1174` deliberately did not force this swap or expand `resolve-blockers.js`'s (and `fetchNativeDependencies`' shared) output shape, since doing so ripples into `bin/lib/preflight-records/preflight-records.js`'s own consumption of the same function and its existing `assert.deepEqual` tests pinning the exact `{blockedBy, openBlocker}` shape — a larger, separate change deserving its own review.

## Deliverables

- Extend `bin/lib/issues/native-dependencies.js`'s `fetchNativeDependencies` to also compute `openBlockerIds: number[]` per record (additive — the existing `blockedBy`/`openBlocker` fields stay unchanged), reusing the same per-blocker `state === 'OPEN'` filter `partitionByOpenNativeBlockers` already applies.
- Update `preflight-records.js`'s existing `assert.deepEqual` tests pinning the exact `{blockedBy, openBlocker}` Map-value shape to account for the new field (or scope the assertions to the specific fields they care about, so a future additive field doesn't require touching them again).
- Rewrite `plugin/skills/dispatch/queue-pull-script.md`'s native branch to call `bin/resolve-blockers.js` with the eligible candidates' comma-joined numbers, then reconstruct the `partitionByOpenNativeBlockers`-equivalent partition from the CLI's `{blockedBy, openBlocker, openBlockerIds}` output instead of hand-rolling the query and calling `gh api graphql` directly.

## Acceptance Criteria

- `queue-pull-script.md`'s native branch contains no hand-rolled `gh api graphql -f query=...` instruction.
- Dispatch's Blocked-exclusion report still names the specific open blocker id(s) for each excluded candidate, unchanged from today's behavior.
- `node --test tests/bin-lib/preflight-records/` and `node --test tests/resolve-blockers-cli.test.js` pass with the extended shape.
- `npm test` passes.

## Technical Approach

Mirror #1174's own resolve-blockers.js wiring pattern for unblocked-records.md, but first extend `fetchNativeDependencies` additively (see Deliverables), verify the addition doesn't change `preflight-records.js`'s existing consumption (it destructures only named fields, per read at #1174's investigation — an extra field should be safe there), then rewrite `queue-pull-script.md`'s native branch's `node -e` block to consume the richer shape in place of the raw `repoData` object `partitionByOpenNativeBlockers` currently expects.

### Key Files

- `plugin/bin/lib/issues/native-dependencies.js` — `fetchNativeDependencies`, additive `openBlockerIds` field
- `plugin/bin/resolve-blockers.js` — pass the new field through to its own output unchanged
- `plugin/bin/lib/issues/record.js` — `partitionByOpenNativeBlockers`, the per-blocker-open-id logic to reuse/match
- `plugin/skills/dispatch/queue-pull-script.md` — the hand-rolled block to replace
- `tests/bin-lib/preflight-records/preflight-records.test.js` — existing `assert.deepEqual` shape pins to update
- `tests/resolve-blockers-cli.test.js` — extend for the new field

## Gotchas

- `fetchNativeDependencies` is shared with `preflight-records.js`'s own N-record batch call — an additive field is intended to be backward-compatible, but verify by running that suite, don't just assume.
- Preserve `resolve-blockers.js`'s existing single-aliased-call-per-invocation guarantee — don't let this refactor introduce a second GraphQL call.

## Original request

Found during #1174's build (multi-spec session, PR #1265) — #1174's own investigation confirmed dispatch's queue-pull-script.md has the identical hand-rolled pattern but a genuinely different downstream shape need, so it was deliberately not force-fit into #1174 and filed here instead.
