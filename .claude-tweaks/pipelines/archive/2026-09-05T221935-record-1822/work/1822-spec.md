# 1822: Sweep's Next Actions buries the already-staged tidy --approve behind dispatch/refine picks

Origin: capture

## Current State

`/claude-tweaks:sweep`'s `## Next Actions` block (`plugin/skills/sweep/SKILL.md`) renders in a
fixed order: the top `/claude-tweaks:backlog attention` pick (when present, replacing the
`/claude-tweaks:dispatch` slot per the precedence rule) -> `/claude-tweaks:dispatch {grants}` ->
`/claude-tweaks:tidy --approve` -> `/claude-tweaks:backlog attention`.

Observed live on a real sweep run: tidy staged only two trivial, already-vetted items (one
`docs/REGISTRY.md` line addition, three stale `bot:in-progress` label removals on issues whose
claims were already stale/released) -- yet `tidy --approve` rendered third in the Next Actions
block, after a `backlog refine #N` re-authorization pick and a `dispatch` call that kicks off
new autonomous builds. The user flagged this live as counter-intuitive: closing out a fully
vetted, zero-judgment batch should be the cheapest, fastest thing to clear -- not buried behind
two heavier, judgment-requiring actions.

## Deliverables

- Re-examine `sweep/SKILL.md`'s `## Next Actions` fixed ordering (`/claude-tweaks:dispatch` /
  `/claude-tweaks:tidy --approve` / `/claude-tweaks:backlog attention`, with the needs-you
  precedence rule only ever replacing the `/dispatch` slot) and decide whether "apply
  already-staged, mechanically-vetted proposals" should sort ahead of "start new autonomous
  work" or "resolve a re-authorization."
- Either (a) reorder so `tidy --approve` leads whenever this run's tidy step staged anything,
  with dispatch/refine picks following, or (b) if the current order is intentional, add one
  line to `sweep/SKILL.md` stating the rationale so a future reader isn't left guessing.
- Check whether the same ordering question applies to `tidy/SKILL.md`'s own Next Actions
  derivation rule (the "Approve ({N})" line's position relative to a Yours group's batch line)
  for consistency across both skills.

## Acceptance Criteria

- `sweep/SKILL.md`'s `## Next Actions` section either reorders `tidy --approve` ahead of
  `dispatch`/the needs-you pick whenever tidy staged anything this run, or documents why the
  current order is deliberate.
- No change to the underlying tidy/refine/dispatch mechanics -- this is purely about the
  recommended ordering of paste-ready lines in the close-out render.
