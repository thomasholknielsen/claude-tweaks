# 260: Routine preamble: read the setup log, finish self-heal with an executed skill (dispatch excluded)

Surface: infra

## Overview

Extend the canonical routine prompt preamble in `skills/_shared/routine-template-schema.md` with two clauses — read `$HOME/claude-cloud-setup.log` when the build-resolution rungs come up empty, and complete a successful mid-session self-heal by executing the installed skill's SKILL.md manually when the frozen Skill catalog cannot invoke it (with `/claude-tweaks:dispatch` excluded) — then fan the preamble out byte-identically to all six routine templates and bump each `template_version`. This makes every routine firing end in an executed skill regardless of whether the platform ever runs the environment Setup script, and turns every future setup failure into self-documenting evidence. The manual-execution fallback is the behavior the scheduled docs-health firing improvised on 2026-08-09 (installed plugins mid-run, read SKILL.md, filed a correct finding, #245). That is a single observed instance — accepted explicitly: the clause exists to make an already-observed-working recovery deterministic, not to claim statistical validation.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- The Setup-script field line itself (#259).
- Prose corrections to cloud-parity claims (#261).
- Re-syncing the five live routines (post-release operation, see parent #258).
- Notification wiring for degraded firings (#210).

## Current State

- `skills/_shared/routine-template-schema.md` — the `## Standard prompt preamble` fenced block: four resolution rungs, the `claude plugin list --json` clause, and a self-heal block ("Go straight to `bash scripts/claude-cloud-setup.sh` …") that ends by re-running the resolved-build line; nothing tells the agent what to do when the Skill tool still can't invoke the kickoff afterward (measured 2026-08-09: two agents hit exactly that wall and diverged — one stopped, one improvised).
- Six templates, byte-identical preambles, versions at decomposition time: `code-health` 6, `dispatch` 6, `docs-health` 6, `harness-health` 6, `journey-health` 7, `tidy` 7 (verified against the tree 2026-08-09; re-verify before editing).
- `tests/routine-template-schema.test.js` — derives the canonical preamble **at run time** by parsing the `## Standard prompt preamble` fenced block out of `routine-template-schema.md` (`canonicalPreamble()`), then byte-compares each template against the derived string. There are no hardcoded preamble or version literals in the test file, and it deliberately does **not** check that a version incremented (its own documented anti-pattern).

## Deliverables

- [ ] **Log-read clause**, inserted immediately **before** the existing self-heal sentence ("Go straight to `bash scripts/claude-cloud-setup.sh` …"): on `unresolved`, read `$HOME/claude-cloud-setup.log` and print exactly one line — `claude-cloud-setup.log: absent — the environment Setup script left no trace in this container (not executed, or its write failed)` or `claude-cloud-setup.log: present — tail: {last 5 lines}`. Absence is stated as evidence, not proof — the wording above already carries the third bucket (a failed log write is indistinguishable from non-execution from inside the container, and the line says so).
- [ ] **Self-heal completion clause**, inserted immediately **after** "re-run the resolved-build line once", before the `Then:` kickoff line: if invoking the kickoff skill via the Skill tool then fails with an unknown/unrecognized-skill error (the deterministic signal that the session's skill catalog was frozen before the install), read `{path}/skills/{skill}/SKILL.md` — where `{path}` is the path component the just-printed resolved-build line reported (it exists by construction, since this clause only fires after that line succeeded) — and execute that file's instructions directly, following them as written (frontmatter, interaction-style directive, steps) rather than summarizing. Carve-out, stated with its principle: **if the kickoff below is `/claude-tweaks:dispatch`, do not execute it manually — report the degraded sandbox and stop.** Dispatch claims queue records and triggers builds/merges — standing effects beyond a report; any future routine whose skill claims work or writes beyond report-only surfaces gets the same exclusion.
- [ ] All six `skills/*/routine-template.yml` prompts regenerated byte-identical to the new canonical preamble (kickoff line excepted).
- [ ] All six `template_version` values bumped by exactly one from their **tree values at edit time** (not this record's recorded numbers). Conflict rule: if a concurrent change lands first (e.g. the #215 family), re-read the merged tree and recompute the bump — never resolve a version conflict by keeping both sides or picking the higher literal (recompute, per IL-99).
- [ ] `npm test` green. No test-file edits are expected (the suite derives its expectations; see Current State) — if the test file turns out to need edits, that is a finding to surface, not a routine step.

## Acceptance Criteria

1. The canonical preamble contains both new clauses at the stated insertion points, with the log-read clause's two exact output-line formats as specified in Deliverables.
2. The manual-execution clause names its trigger signal (unknown-skill error from the Skill tool after successful re-resolution), its path source (the resolved-build line's `{path}`), and the dispatch exclusion with its stated principle — all inside the shared preamble text; no per-template variance; all six template prompts remain byte-identical modulo their final kickoff line.
3. `git diff {merge-base}..HEAD` for this leaf's branch shows each of the six templates' `template_version` lines changed, each new value = its pre-edit tree value + 1 (checked against the branch's own base, so a concurrent bump landing before this build doesn't false-fail it).
4. `npm test` passes.

## Technical Approach

Edit the preamble once inside `_shared/routine-template-schema.md`'s `## Standard prompt preamble` fenced block, then mechanically propagate to the six templates — the schema test's runtime byte-parity check against that same block is the verifier. The carve-out is one sentence keyed on the kickoff skill name, so it costs nothing in the five templates it doesn't apply to.

## Gotchas

- The model-profile family (#215; leaves #219–#223, several `auto:build`) may touch routine templates concurrently — re-verify each template's current `template_version` and preamble text against the tree immediately before this leaf builds (IL-109); the numbers recorded here matched the tree at decomposition time but expire.
- A green schema test does not prove versions incremented — the suite checks byte-parity and shape only; AC 3's merge-base diff is the check that fails red when a bump is missing (this repo has shipped a six-template preamble edit with zero bumps and a green suite before).
- Manual SKILL.md execution bypasses the Skill tool's plumbing — the clause instructs following the file as written, including its blockquoted interaction-style directive (the line every claude-tweaks SKILL.md opens with), not a summary of it.
- The log-read clause's `{last 5 lines}` keeps the report bounded — the full log stays on disk for a deeper look within the same session.
