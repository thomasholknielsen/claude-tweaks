# 1545: flow: derive the ceremony profile from the diff for headless firings -- standard wrap-up ran ~8min on a +75/-2 test-only change

Surface: infra

## Current State

A headless dispatch firing ran the full `standard` wrap-up ceremony — five-lens reflect, the complete curation-engine registry pass, residue sweep, ledger routing — for a diff that was exactly `tests/wrap-up-registry-pin.test.js` (+75/−2) plus the materialized spec doc (Dispatch hub run #9, 2026-08-26, group [#251], PR #1518). Call 2's wrap-up ran full-mode reflect (all five lenses), the full registry evaluation (skills/docs/journeys rows all judged clean), a blast-radius residue sweep that surfaced only pre-existing residue from *other* runs (29 stale merged branches, routed to a staged ledger record), and the ledger machinery — none of which produced an action for this change. ~8 of the firing's 43 minutes went to this ceremony. The merge title itself was prefixed `[fast-lane]`, but `config.yml` carried `ceremony-profile: standard` — the two disagreed, and the wider profile is what actually ran.

## Deliverables

Derive the ceremony profile from measurable facts about the change, for headless firings, instead of defaulting to `standard`:

- Diff size, file count, and surface (test-only / docs-only / backend) computed at the point dispatch composes the group's `config.yml`, or at the point flow's Manifesto computes levers in a headless run.
- Small, low-surface headless changes (matching the test-only pattern above) default to `ceremony-profile: fast-lane`.
- An escape hatch: any review or reflect safety finding upgrades the profile to `standard` in place, even after a `fast-lane` default was set — the derivation is a default, not a ceiling.

## Acceptance Criteria

- A headless firing whose diff is test-only (or otherwise matches the small/low-surface pattern this issue evidences) is assigned `ceremony-profile: fast-lane` at config-composition time, not `standard`.
- A headless firing whose review or reflect step surfaces a safety finding runs the full `standard` ceremony regardless of what the diff-based default computed — the escape hatch actually fires, it isn't just documented.
- The dispatch-composed `config.yml`'s `ceremony-profile` value and the eventual merge-title prefix (`[fast-lane]` / `[standard]`) never disagree for a run that went through this derivation — the run #9 mismatch (title said `[fast-lane]`, config said `standard`) cannot recur for a diff this derivation classifies.
- A non-headless (interactive) `/claude-tweaks:flow` run is unaffected — this derivation is scoped to headless firings per the Affected component below, not a change to the interactive Manifesto's existing ceremony question.

## Technical Approach

Add a diff-facts computation (size, file count, surface) at whichever point currently defaults headless `ceremony-profile` to `standard` — `dispatch/task-prompt.md`'s `config.yml` composition, or flow's own Manifesto lever computation when invoked headlessly — and use it to set the default, with the existing review/reflect-driven upgrade path as the guard that can override it upward.

### Key Files

- `plugin/skills/dispatch/task-prompt.md` — `config.yml` composition for a dispatched firing, if this is where the default is set
- `plugin/skills/flow/SKILL.md` — Manifesto's headless lever computation, if the default is set there instead
- `plugin/skills/wrap-up/SKILL.md` — the existing standard/fast-lane ceremony branches this derivation feeds into, and the safety-finding upgrade path it must plug into

## Gotchas

- The derivation must never *downgrade* a profile already set to `standard` by an upstream decision (e.g. an explicit project policy, or a prior review finding) — it only supplies the default when nothing has decided yet, and the escape hatch is strictly upward (fast-lane → standard), never the reverse.
- "Test-only" and "docs-only" surface detection needs to be robust to a diff that touches a test file *and* a small amount of production code (e.g. a one-line fix plus its regression test) — get the surface classification boundary right, or a real behavioral change could get misclassified as test-only and wrongly default to `fast-lane`.
- Keep the merge-title prefix and `config.yml`'s `ceremony-profile` value derived from the same computation (or one directly from the other) so the two structurally cannot disagree the way they did in the evidence run.
