# 1098: hooks context: add classifyOwnership — composite session + worktree-binding ownership predicate

Surface: backend

## Overview

Foundation sub-issue for the #965 run-state ownership hardening (parent has the full rationale). Adds one new exported predicate to `plugin/bin/lib/hooks/context.js` — `classifyOwnership(callerIdentity, runState)` — that decides whether a caller owns a pipeline run using composite identity: session id AND worktree binding. Motivation (measured 2026-08-20): `CLAUDE_CODE_SESSION_ID` is shared across all subagents of a session, so session-id equality alone cannot distinguish N parallel sibling agents; every ownership check that treats it as sufficient reads a sibling's run as "mine". This sub-issue ships the predicate and its unit-test matrix only — no existing call site changes behavior yet (the consuming changes are the two dependent sub-issues).

**Complexity:** Medium
**Estimated tasks:** 4

## Deliverables

- [ ] Export `classifyOwnership({ sessionId, cwd }, runState)` from `plugin/bin/lib/hooks/context.js`, returning exactly one of `'mine' | 'foreign' | 'indeterminate'` per the semantics table in Data / API Surface below.
- [ ] Path comparison reuses the same realpath canonicalization approach `findRunByWorktreePath` already uses (canonicalize where paths exist, keep the as-given form as fallback; partial-failure rule per Technical Approach) — extract a small shared helper rather than duplicating the try/realpath idiom a third time. - [ ] Unit-test matrix in a new `tests/bin-lib/hooks/classify-ownership.test.js` (or the repo's chosen colocated equivalent) covering every row of the semantics table, including: shared-session sibling (equal session ids, caller cwd inside a different live worktree → `foreign` — the #965 incident shape), distinct session ids (→ `foreign` regardless of cwd), missing session id on either side with binding match (→ `mine`) and with binding mismatch (→ `foreign`), no-binding run with caller in the main checkout (→ `mine` with matching ids, `indeterminate` with a missing id), recorded worktree deleted from disk (→ `indeterminate`, fail-open — never `foreign` on unprovable evidence), and cwd given as a symlinked/relative variant of the recorded worktree (→ `mine`).

## Acceptance Criteria

1. `classifyOwnership` returns `foreign` when both session ids are present and different, regardless of cwd — current behavior preserved as-is.
2. `classifyOwnership` returns `foreign` when session ids are equal (or either is missing) but `runState.worktree` is recorded, exists on disk, and the caller's cwd canonicalizes to inside a different registered worktree — the new sibling arm.
3. `classifyOwnership` returns `mine` when the caller's cwd canonicalizes to inside the recorded worktree, and for a binding-less run when the caller is in the main checkout with session ids both present and equal (the table's literal condition — "compatible" is not a looser standard).
4. `classifyOwnership` returns `indeterminate` (never `foreign`) when the recorded worktree no longer exists on disk, and for a binding-less run with no session evidence — preserving `resolveRun`'s documented asymmetry ("an unowned run may still be ours; a run owned by someone else never is").
5. All existing exports of `context.js` behave identically at the observable level — no existing test is modified, full `npm test` green (an internal refactor onto the shared helper is fine as long as this holds).
6. Reverting the predicate implementation (keeping the tests) makes the new suite fail — verified once during development (test discrimination check).

## Technical Approach

Pure decision function: no writes, no events, no resolution — callers own what to do with the verdict. It MAY call `worktree-detect.js`'s existing helpers (`mainCheckoutRoot()` and the caller-worktree identification it already provides), which shell out to git via `git-exec.js` — the same dependency footprint `pre-tool-use.js` already carries; do NOT attempt an fs-only reimplementation of worktree identity. No repo-wide worktree enumeration is needed: "inside a different live worktree" is decided by resolving the **caller's own** worktree root from `cwd` (the same detection `worktree-detect.js` already performs) and comparing it against the recorded binding — one lookup for the caller, one canonicalization for the binding.

Definitions the table below depends on (pin these in code and tests):

- **`cwd` is always absolute** — callers pass an absolute path (same convention as `findRunByWorktreePath`'s pre-resolved `targetPath`); the function does not resolve relative input against `process.cwd()`.
- **"missing" session id** = not a non-empty string (`typeof x !== 'string' || x === ''`) — the same check `context.js` already uses for `state.sessionId`.
- **"recorded, exists"** = `fs.realpathSync(runState.worktree)` succeeds and the result is a directory; registry membership is NOT required (a reaped-but-still-recorded path fails realpath → `indeterminate`).
- **Partial canonicalization**: canonicalize each side independently where realpath succeeds, keep the as-given form where it fails, then compare best-effort forms (path-prefix containment after normalization). A comparison where one side kept its as-given form can still produce `mine` on an exact/containment match; it can never produce `foreign` on its own — an unprovable mismatch degrades to `indeterminate`.

### Data / API Surface

`classifyOwnership({ sessionId, cwd }, runState) -> 'mine' | 'foreign' | 'indeterminate'`

| session ids | binding (`runState.worktree`) | caller cwd | verdict |
|---|---|---|---|
| both present, different | any | any | `foreign` |
| equal or either missing | recorded, exists | inside recorded worktree | `mine` |
| equal or either missing | recorded, exists | inside a different live worktree of the same repo | `foreign` |
| equal or either missing | recorded, exists | main checkout (no worktree) | `indeterminate` |
| equal or either missing | recorded, exists | outside every known worktree and not the main checkout (unrecognized path) | `indeterminate` |
| equal or either missing | recorded, gone from disk (realpath fails) | any | `indeterminate` |
| both present and equal | none | main checkout | `mine` |
| both present and equal | none | inside any live worktree | `indeterminate` |
| either missing | none | any | `indeterminate` |

**Consumer contract (fail-open):** this predicate only classifies; it enforces nothing. The fail-open property — `indeterminate` must never be escalated to a refusal/denial beyond each call site's existing behavior — is an obligation on the two dependent sub-issues (#1012, #1099), stated here so their reviews hold them to it.

## Gotchas

- `CLAUDE_CODE_SESSION_ID` identifies the session, never the agent — measured 2026-08-20 (#965): all subagents inherit the parent session's id. Never treat its equality as sufficient ownership evidence; that is the whole point of this predicate.
- Do not "fix" `resolveRun`'s sanctioned console-execution exception (its header comment explicitly forbids tightening it) — this sub-issue adds a predicate; it does not tighten any existing resolution.
- Fail open on unprovable evidence: a deleted recorded worktree, an unreadable path, or a caller cwd outside any known worktree must never produce `foreign` — corruption prevention must not turn into denial of legitimate janitorial/post-teardown calls.
- `#1065` and `#1017` (open) touch `worktree-detect.js`/run-dir anchoring; keep this unit's use of `worktree-detect.js` read-only to avoid a physical conflict.
- Test hermeticity: spawn-based hooks tests in this repo have been bitten by an inherited `PIPELINE_RUN_DIR` (#1038) — pure unit tests here should not spawn, but if any case does, clear that env var explicitly.
