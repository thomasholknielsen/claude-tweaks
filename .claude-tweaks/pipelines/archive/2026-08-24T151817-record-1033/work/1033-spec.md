# 1033: Declined-learning store: fingerprint-only matching cannot support its own acceptance criteria

Origin: agent-held deferral from #849's final whole-branch review (declined-learning fingerprint store) — items 2-5 of that review, ruled non-blocking for #849's own merge since the store/write paths are correct and forward-compatible with this fix, but the feature doesn't yet deliver on its own acceptance criteria in practice

Defer-reason: genuinely-larger

## Current State

#849 built `plugin/bin/lib/declined-learning/store.js` (fingerprint -> {declinedAt, reason, source}) and wired it into `/feedback`'s decline path and `/wrap-up`'s reflect insight routing. The final review found the wiring correct but the *matching mechanism* insufficient for the acceptance criteria it was meant to satisfy:

- `/feedback`'s side (`plugin/bin/lib/transcript-judge/watermark.js`'s `formatOffsetClause`) renders dismissed fingerprints as opaque 8-hex SHA-1 slices (`fingerprintFromBasis`, `bin/lib/health-core/fingerprint.js`) directly into the judge's dispatch prompt — an LLM reading a transcript has no way to compute a candidate finding's own fingerprint to compare against a hash, so it cannot act on "omit findings matching them." Additionally, nothing on the `/feedback` side ever calls `lookupDecline` — only `recordDecline` (on decline) and `listDeclinedFingerprints` (into the watermark payload) are wired; a re-surfaced declined finding still gets fully re-drafted and re-scrubbed for the human to decline a second time.
- `/wrap-up`'s reflect side (`plugin/skills/reflect/full-mode.md`'s Prior-decline annotation) fingerprints each insight via `createFingerprint('reflect', ['description'])` — free-form LLM prose, normalized only by whitespace-collapse + lowercase (`bin/lib/health-core/fingerprint.js`'s `normalizeText`). Two runs must produce byte-identical insight sentences (modulo case/spacing) to match, which in practice they rarely will — the annotation mechanism is wired correctly but fires rarely.
- Separately, `session-evaluation.md`'s watermark payload snapshots `dismissedFingerprints` at watermark-write time (which happens before Step 7's declines in the same run), rather than reading `listDeclinedFingerprints` fresh at judge-dispatch time — a likely one-run lag before a decline's fingerprint reaches the offset clause at all.

## Deliverables

Redesign the store entry / lookup contract so a human-legible signal travels alongside (or instead of) the opaque fingerprint, so both consumers can actually act on it:

- Add a `subject` field (or equivalent) to the store's entry shape — e.g. the draft's `fingerprintBasis.summary` for feedback, the insight text for reflect — so a re-surfacing finding/insight can be judged for equivalence by an agent reading the store directly, not by exact-hash comparison alone.
- Wire `lookupDecline` into `/feedback`'s own dedup step (Step 4, where the fingerprint is already computed) so a declined finding is annotated there — mirroring reflect's "annotated, never silently suppressed" treatment — rather than relying solely on the judge prompt's opaque-hash offset clause.
- Change `session-evaluation.md`'s watermark payload to read `listDeclinedFingerprints({ source: 'feedback' })` fresh at dispatch time instead of snapshotting it into the watermark write, removing the one-run lag and the payload's now-unnecessary explanatory comment.
- Sweep the final review's Minor findings for anything worth folding in at the same time (7 items — H3 section-nesting cosmetic issue in `full-mode.md`, `docs/plugin-structure.md` missing the new `bin/lib` family, `.gitignore` comment-block scoping, `source: 'wrap-up'` naming when reflect runs standalone, no pruning/TTL on the store, reflect's judge dispatch always rendering an inert "previously declined: none" segment — full detail was in #849's final-review report, `.superpowers/sdd/2026-08-20-declined-learning-store/` in that run's worktree; summarized in the run's decisions/ledger before archival).

## Acceptance Criteria

- A finding declined at `/feedback` Step 7 that re-surfaces in a later run is annotated at Step 4's dedup (not just theoretically omittable by an unreachable judge instruction).
- A reflect insight that re-surfaces with materially the same meaning (not just byte-identical text) is annotated, verified against at least one case where the wording differs but the subject is the same.
- `session-evaluation.md`'s watermark payload no longer needs to explain a snapshot-timing caveat because there isn't one.
- Existing #849 tests (`tests/bin-lib/declined-learning/store.test.js`, `tests/bin-lib/transcript-judge/watermark.test.js`, `tests/feedback-watermark-prose.test.js`) still pass, extended to cover the new `subject` field and the feedback-side `lookupDecline` wiring.
