# 1503: qa-agent/browse skill's agent-browser guidance is stale against the pinned agent-browser v0.27

Surface: backend

## Current State

The `qa-agent`/`browse` skill's agent-browser command reference (`plugin/skills/browse/agent-browser-reference.md`, cited by `plugin/skills/browse/SKILL.md` and `plugin/agents/qa-agent.md`) is pinned to agent-browser v0.27, but the documented command vocabulary doesn't reflect several real behaviors of that pinned version. Every QA story-generation and QA-execution session currently rediscovers these facts independently rather than reading them from the skill.

## Deliverables

Update `plugin/skills/browse/agent-browser-reference.md` (and `SKILL.md`/`qa-agent.md` if either restates the affected guidance locally) to document, for the pinned agent-browser v0.27:

- `find`'s action argument only supports `click`/`fill`/`check`/`hover` — no `select`, `press`, or `type`. Document the fallback for a `select` interaction: a full `snapshot -i -c` followed by a separate top-level `select @eN value` call.
- `find role <role> ... --name X` resolves the `button` role but not `link` or `heading` — locating a link or heading by role silently fails to match; QA prompts must use a different locator (text/testid/label) for those roles.
- `click` does not auto-scroll the target into view — a below-the-fold click reports success but lands nowhere. Document the mitigation (pinning a tall viewport) so QA prompts guard against this explicitly.
- `screenshot` can fail with an OS-level error under concurrent sessions, and appears to reject an output path containing a space — document both as known limitations.
- The distinction between plain `snapshot` (for a static-text assertion) and `snapshot -i -c` (a different purpose — locating interactive refs) isn't called out anywhere the skill's prompts reference; document it explicitly.

## Acceptance Criteria

- [ ] `agent-browser-reference.md` documents the four action verbs `find` actually supports and the `snapshot -i -c` + top-level `select @eN value` fallback for a select interaction.
- [ ] `agent-browser-reference.md`'s role-locator guidance states that only `button` reliably resolves via `find role`, not `link`/`heading`.
- [ ] `agent-browser-reference.md` documents that `click` does not auto-scroll, with the tall-viewport mitigation QA prompts should apply.
- [ ] `agent-browser-reference.md` documents `screenshot`'s concurrent-session OS-level failure mode and its rejection of paths containing spaces.
- [ ] `agent-browser-reference.md` explicitly distinguishes plain `snapshot` (static-text assertions) from `snapshot -i -c` (interactive-ref lookup), and any prompt guidance elsewhere in the skill that conflates the two is corrected.
- [ ] No other command-reference table in `SKILL.md`/`qa-agent.md` still restates the pre-fix guidance (single-source-of-truth check, matching the existing "no local copy" convention already noted in `agent-browser-reference.md`).

## Technical Approach

Pure documentation change, scoped to the pinned agent-browser v0.27 command surface — no code, no new behavior. Edit the reference table(s) and any adjacent prose in `agent-browser-reference.md` to add the five facts above; cross-check `SKILL.md`'s own command-reference/Anti-Patterns tables and `qa-agent.md` for any restated guidance that would now be inconsistent, per the "single source of truth, no local copy" principle `agent-browser-reference.md` already states for its Anti-Patterns table.

### Key Files

- `plugin/skills/browse/SKILL.md` — check for restated command-reference content that needs the same update

## Gotchas

- These facts are version-pinned to agent-browser v0.27 specifically — if the plugin's pinned version changes later, this guidance needs re-verification against the new version rather than being assumed to still hold.
- `find role button ... --name X` resolving but `link`/`heading` silently failing to match is easy to miss in testing — the command exits without an error, it just doesn't find the element, so verification of this fix should include a negative-case check (attempt a `link`/`heading` role find and confirm the doc's guidance to use a different locator is followed).
