# 1099: pre-tool-use E-checks + resolveRun attribution: classify same-session sibling worktrees as foreign

Surface: backend

## Overview

Enforcement-layer half of the #965 run-state ownership hardening (parent record has the full rationale): the two inline `owner !== caller` session-id comparisons in `plugin/bin/lib/hooks/pre-tool-use.js`, and `resolveRun`'s session-scoped `attribution: 'session'` path in `plugin/bin/lib/hooks/context.js`, all assume session id ≡ actor. Because `CLAUDE_CODE_SESSION_ID` is shared across all subagents of a session (measured 2026-08-20, #965), a sibling agent in its own worktree is misclassified as the run's own session: the E-checks take the same-session branch (deny) instead of the foreign branch (warn/allow + event), and `resolveRun` confidently returns a sibling's run as the caller's own. These fail toward deny/warn rather than corruption — lower stakes than the mutating verbs — but they are the same broken equivalence and complete the ownership contract.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- No change to any hooks.js mutating verb — that is the mutating-verbs sibling sub-issue (#1012).
- No change to which E-checks exist, their deny/warn/allow outcomes per classification, or their event vocabulary (`wd-foreign-teardown`, `wd-foreign-session`, `wd-deny`, `wd-push-mismatch`) — only how "foreign" is decided.
- Not implementing #607's deliverables (fallback-attribution breadcrumb hygiene) — #607 stays independent; this unit only touches the `attribution: 'session'` arm, not the `'fallback'` arm #607 targets.
- No change to the sanctioned console-execution exception documented at `resolveRun`'s header.

## Prerequisites

| Spec | Title | Status |
|------|-------|--------|
| #1098 | hooks context: add classifyOwnership | open |

## Current State

- `plugin/bin/lib/hooks/pre-tool-use.js` — two sites compare `state.sessionId` against the hook payload's `ctx.input.session_id`. Teardown path: `if (owner && caller && owner !== caller)` → foreign branch (allow + `wd-foreign-teardown` event + warning); everything else — same-session, unowned target, or missing identity on either side — falls through to one deny. Commit path: the same `owner && caller && owner !== caller` guard → foreign branch (allow + `wd-foreign-session` event + systemMessage); everything else, missing-identity cases included, falls through to `wd-deny` (confirmed against the code — the missing-identity case has no separate branch today; "preserve existing behavior" for `indeterminate` means landing in these same fall-throughs). The hook payload's `session_id` is the same shared session identity as the env var. The teardown site classifies the **target** run (`hit.state`, found by worktree path); the commit site classifies the caller's **own resolved** run (`ctx.runState`) — pass each site its own `state` object.
- `plugin/bin/lib/hooks/context.js` — `resolveRun(cwd, env, sessionId)`: with a known session id, returns the first run whose `state.sessionId === me` as `attribution: 'session'`; under shared ids the first such run may be a sibling's. `classifyOwnership` (prerequisite sub-issue): verify the shipped signature and verdict strings against that record's Data / API Surface table at build start, before writing any call.
- Tests: the pinning surface for existing behavior is `tests/hooks-gate-coverage.test.js` plus every suite exercising `resolveRun` — `hooks-run-arg-anchoring.test.js`, `hooks-run-attribution.test.js`, `hooks-context.test.js`, `hooks-dispatcher.test.js`, `teardown-gate.test.js`, `skill-invocation.test.js`, `hooks-spec-status.test.js`, `wrap-up-engine-run-dir-anchoring.test.js` (enumerated by `grep -rl "resolveRun" tests/`; re-run the grep at build time in case the list moved).

## Deliverables

- [ ] Both `pre-tool-use.js` comparison sites decide foreign-vs-own via `classifyOwnership({ sessionId: ctx.input.session_id, cwd: ctx.cwd }, state)` instead of raw id equality: verdict `foreign` takes the existing foreign branch, `mine` the existing same-session branch, `indeterminate` preserves each site's current missing-identity behavior (teardown path: deny; commit path: fall through to `wd-deny`) — outcome semantics per classification unchanged, only the classifier swapped.
- [ ] `resolveRun`'s session-scoped loop skips a run whose `classifyOwnership` verdict against the caller is `foreign` (sibling's bound run) instead of returning it as `attribution: 'session'`. **Only `foreign` skips**: an `indeterminate` verdict (e.g. the recorded worktree is unresolvable) keeps today's behavior and is still returned as `attribution: 'session'` — fail-open, and what keeps single-session resolution byte-identical. "Single-session" here means: no non-terminal run bound to a live worktree other than the caller's own under the same session id — in that scope, order and results are unchanged.
- [ ] Pinning tests: (a) existing single-session scenarios in the hooks suites pass unchanged — zero edits to existing assertions; (b) new cases: same session id + caller cwd in worktree A vs a run bound to worktree B → teardown path classifies foreign (allow + `wd-foreign-teardown`), commit path classifies foreign (allow + `wd-foreign-session`), `resolveRun` skips the sibling run and falls through to its unowned/null result.

## Acceptance Criteria

1. A sibling agent (identical session id, own worktree) tearing down or committing against another sibling's bound run takes the foreign branch at both `pre-tool-use.js` sites — asserted via emitted event type and allow/deny outcome. The dual case is asserted alongside it: the run's own session with cwd inside the recorded worktree still classifies `mine` and takes the same-session branch at both sites.
2. `resolveRun` with a session id never returns `attribution: 'session'` for a run whose recorded worktree is a different live worktree than the caller's cwd.
3. Every existing `tests/hooks-gate-coverage.test.js` and hooks-suite assertion passes without modification — single-session behavior is byte-identical.
4. Reverting the pre-tool-use/context changes (keeping the new tests) makes the new tests fail.
5. Full `npm test` green.

## Technical Approach

Both sites already have `ctx.cwd`/`ctx.input` in scope — construct the caller identity once per check, call the predicate, and map its three verdicts onto each site's existing branches. In `resolveRun`, apply the predicate only inside the `owner === me` arm (the `unowned` fallback arm is #607's territory and stays untouched). Do not add new event types or messages; the fix is purely which existing branch fires.

### Data / API Surface

No new exports. Verdict→branch mapping at the two pre-tool-use sites: `foreign` → existing foreign branch; `mine` → existing same-session branch; `indeterminate` → each site's existing fall-through (teardown: the collapsed deny; commit: `wd-deny`) — an unowned-but-bound target run whose binding doesn't contradict the caller classifies per the predicate's table (typically `indeterminate` from the main checkout, `mine` from inside the binding), landing in the same branches those inputs reach today. In `resolveRun`'s loop: `foreign` → skip; `mine`/`indeterminate` → return (current behavior). No new denials are introduced anywhere — `indeterminate` maps exclusively onto branches that already fire for those inputs, so the hooks contract's never-break-a-session invariant is untouched.

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — the two comparison sites
- `plugin/bin/lib/hooks/context.js` — `resolveRun`'s session-scoped arm
- `tests/hooks-gate-coverage.test.js` (+ the resolveRun-covering hooks suite) — new sibling cases

## Gotchas

- The commit-path's deny (`wd-deny`) for same-session wrong-place work is a *feature* — a sibling reclassified as foreign gets allow+warn, which is the designed cross-actor behavior. The safety invariant "cwd inside the recorded worktree ⇒ `mine`" is a requirement on the prerequisite's predicate (its table's second row), restated in AC1's own-session test case here — not an assumption to eyeball.
- Scope of the worktree-binding proxy: it distinguishes **isolated-worktree** siblings — the incident class. Two same-session actors sharing one worktree (or both in the main checkout) are indistinguishable to the predicate and classify per its same-cwd rows; that residual is accepted and documented, not solved here.
- Worktree-path recycling: a terminal run's dir is reaped/archived by reconcile, but a stale *non-terminal* run recording a since-recycled worktree path is the pre-existing exposure, unchanged by this record — the predicate adds no secondary run-id check, and none is in scope.
- `indeterminate` must not accidentally take the foreign (allow) branch on the teardown path — its current behavior there is deny, and loosening it would weaken E-checks, the opposite of this record's intent.
- #976 (git-plumbing gate bypass), #750 (friction-lens false positives), and #703 all touch `pre-tool-use.js`; #607 touches `resolveRun`'s fallback arm — check merge overlap before building, and keep this unit's diff surgical to the two comparison sites + one loop arm.
- Byte-pinned prose/conformance suites exist repo-wide — run the full suite before merge, not just the hooks files (byte-pinning tests fail only at the merge combination).
