# 1542: dispatch two-call gate: pass a distilled context pack instead of per-call environment rediscovery

Surface: infra

## Current State

Each of a dispatch firing's actors — the dispatching session and both `dispatch/two-call-gate.md` Task calls — re-derives the same environment facts from scratch: plugin root, run-dir paths, resolved policy values, and canonical CLI invocation shapes. A live headless `next` firing (Dispatch hub, run #9, 2026-08-26, 43m10s / $21.36 total) shows this concretely: `CLAUDE_PLUGIN_ROOT` was unset and rediscovered independently by the dispatcher, call 1, and call 2; call 1 probed `claim-targets.js --help` / `materialize.js --help`, ran `materialize.js` against the wrong `--run-dir` once (wrote into the pipelines dir, cleaned up, re-ran against the worktree), and hunted for a nonexistent `set-config` CLI before hand-writing `config.yml` from an archived example; call 2 hunted for `log-decision.js` via `find / -maxdepth 6`, had a call rejected on `--reversibility "high (git revert)"` (the enum is `high|med|low|n/a`), and fumbled the claims-registry contents API three times (`?ref=` quoting, `-f ref=` on a GET, a 404) before landing on the git-trees path. None of these were model failures — each was recovered — but all of it is pure rediscovery of facts and signatures the dispatcher already resolved earlier in the same firing.

## Deliverables

A distilled context pack embedded directly in each Task call's dispatch prompt (`dispatch/task-prompt.md`'s composition, invoked from `dispatch/two-call-gate.md`), containing:

- The resolved `CLAUDE_PLUGIN_ROOT` value.
- The group's resolved run-dir path.
- The resolved policy values the call will need downstream (`autonomy`, `integration-model`, `merge-verification`, oversight floors).
- A short table of canonical CLI invocations with their argument enums (e.g. `log-decision.js --reversibility high|med|low|n/a`, `claim-targets.js --run-id … --targets …`, the claims-registry read path).

## Acceptance Criteria

- `dispatch/task-prompt.md`'s Task-prompt composition includes a context-pack section carrying the four items above, populated before the prompt is dispatched.
- A dispatched call no longer needs to probe `--help` flags, search the filesystem (`find`), or trial-and-error the claims-registry API for the specific facts and signatures the pack now supplies.
- The two-call gate's fresh-context property is preserved for *conclusions* (test results, verdicts, review findings) — the context pack carries only environment facts and tool signatures, never a prior call's judgment.

## Technical Approach

Extend `dispatch/two-call-gate.md`'s Task-prompt composition step to resolve the four context-pack fields once (the dispatcher already resolves most of them earlier in the firing) and have `dispatch/task-prompt.md`'s templates embed the pack verbatim into every dispatched prompt.

### Key Files

- `plugin/skills/dispatch/two-call-gate.md` — add the context-pack resolution step ahead of dispatch
- `plugin/skills/dispatch/task-prompt.md` — embed the resolved pack into the Task-prompt template(s)

## Gotchas

- Keep the pack to facts and tool signatures only — pulling in a prior call's conclusions (test results, verdicts) would violate the two-call gate's fresh-context independence property, the thing that makes the second call's review meaningful.
- The canonical CLI invocation table must stay in sync with the actual CLI argument enums (e.g. `log-decision.js`'s `--reversibility` values) — a stale table reintroduces exactly the rejected-call failure mode this issue exists to eliminate.
