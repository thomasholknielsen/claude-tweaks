# 1071: specify: guard shaping mode against decomposition-parent records

Surface: backend

## Overview

`/claude-tweaks:specify`'s shaping mode enters on any bare record reference and rewrites the record into spec shape, stamping `ready`. Nothing checks whether the target is a decomposition parent — a summary record that must never be `ready`. This unit adds a two-tier guard at shaping's entry points: an authoritative marker check (`parent-issue` label / `facets.isParentIssue`) that hard-stops with no prompt and silently strips mis-shape residue, and a legacy body sniff (line-anchored `## Leaves` heading) that stops and asks, offering label repair or a false-positive escape. Headless invocations (`next` firings, `--chained`) and batch/range invocations resolve the sniff tier conservatively to a refusal.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- No new detection code under `plugin/bin/` — the guard is skill prose over signals a full record fetch returns (labels + body); case 1 already fetches these, and case 5's branch fetches the matched record fully before shaping (see Deliverables).
- No native sub-issue GraphQL query tier — rejected in the design (one extra call per record to cover no observed case). The tier-1 leaves pointer is static prose, not a query (see Deliverables).
- No change to `next-mode.md`'s eligibility `EXCLUDE` set — it already excludes `parent-issue`; this unit only adds a backstop note.
- No `/tidy` sweep for legacy unlabeled parents — tier 2's repair option converts them one at a time as encountered.
- No change to decomposition mode — `record-creation.md` creates parents deliberately; the guard exists only on shaping-mode entry paths.

## Gotchas

- The residue strip must never touch `type:*` or `priority:*` (legitimate on parents) or `auto:*`/`bot:*` (other skills' territory) — the carve-out is exactly the five families listed, nothing more.
- "Silent" means no prompt, never unreported: the strip is always named in the guard's output; when a pipeline run directory resolves, it is also logged per `_shared/auto-decision-log.md`.
- The batch message's "nothing shaped" coexists with tier-1 strips having run — the asymmetry is intentional (the strip is repair of unambiguously wrong state, not shaping) and must be surfaced, not hidden: the message names any strip that ran.
- Guard ordering matters: it runs before the `needs:definition` check, so a parent carrying `needs:definition` hits the guard, not the brainstorming redirect.
- The `## Leaves` sniff must be line-anchored; a substring match would false-positive on prose mentioning the word (this very record's body is an example).
- Residual false-negative risk is accepted: a future unlabeled parent bearing neither marker nor a `## Leaves` table escapes tier 2. The 234-record design-time scan grounds this acceptance, and `record-creation.md` applies the marker unconditionally at every parent create, so only hand-authored legacy shapes can reach the gap.
- The shape-anyway escape is deliberately one-shot: it persists no suppress state, so the guard re-prompts on every future invocation against the same record. Do not add a memoized marker — it would be machinery for a case expected to be rare-to-never (all four known tier-2 targets are real parents).
- Write the plan's verification greps case-insensitive and content-anchored; a repo-wide sweep for the carve-out wording should include `_shared/work-record.md`'s consumers, since contract changes there follow expand-contract discipline.
- Do not write the literal placeholder tokens the spec-shaped-body check greps for anywhere in composed prose (paraphrase as "deferred-work markers").

## Decision Rationale

Two-tier detect + silent clean was chosen over: always-hard-stop (no escape for a sniff false-positive), always-ask (prompts on unambiguous labeled parents; conflicts with auto-mode's no-new-mid-flow-stops posture), detect-and-point-only (leaves a `ready` parent polluting the authorization worklist until a /tidy pass), and a native sub-issue graph-query tier (an extra GraphQL call per record covering no observed case). Human decision (Thomas, 2026-08-20): residue cleanup is silent — unambiguously wrong state gets fixed without a click, reported not prompted. In-session rulings (2026-08-20): a batch tier-2 hit refuses like the headless branch because the batch is already fail-all — a prompt could not change the batch's outcome, only add ceremony; the shape-anyway escape stays one-shot because a persisted suppressor is machinery for a case expected to be rare-to-never.
