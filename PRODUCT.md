# Product

## Users

Developers using Claude Code who want a structured development lifecycle instead of ad hoc prompting. They work across capture, brainstorming, spec decomposition, build, review, and wrap-up, often coordinating parallel subagents and worktrees.

## Product Purpose

claude-tweaks adds a complete development lifecycle to Claude Code: capture ideas, challenge assumptions, decompose into specs, build with quality gates, and learn from what was built. Every finding is explicitly resolved (fix now, defer, or accept with reason) — nothing silently drops. Success looks like a repo that stays governed (specs, backlog, GitHub issues) without the user having to remember to do the governance themselves.

## Brand Personality

Precise and disciplined. Rigorous, systematic, no loose ends — output should read as engineered, not decorated. Terminal-native, not consumer-app.

## Anti-references

Not SaaS marketing gloss: no gradient hero sections, no bouncy/elastic animation, no consumer-app cheerfulness, no hero-metric templates. Not corporate-enterprise staidness either — this is developer tooling, not an admin console.

## Design Principles

- Nothing silently drops — every surfaced item is explicitly resolved, and diagrams/docs should make state (done, staged, blocked) visible, not implied
- Quality gates over speed — structure and correctness signals take precedence over visual flourish
- Auto-mode bookends, not scattered stops — long processes collapse to a start config and an end review, not constant interruption
- Governance as code — labels, claims, dedup, and audit trails are real mechanisms, not tribal knowledge; visuals should reflect the actual mechanism, not a simplified fiction of it
- Reversibility and isolation — worktrees, claims, and staged proposals exist so nothing destructive happens by accident

## Accessibility & Inclusion

WCAG AA contrast minimum. No color-only encoding — state and category distinctions must also carry a shape, label, or position cue.
