How claude-tweaks Works with GitHub Issues

Every work record — a captured idea, a health-skill finding, or a human-filed issue — is the same thing underneath: a GitHub issue (or its local-files twin) tracked through one spine, not separate backlog files, tier labels, or per-skill status fields. Six label axes (Type, Origin, Scoring, Stage, Authorization, Bot state) make record state visible and queryable, but a label is a projection of state whose truth lives in the body, the claim ref, or a human's judgment — never the label alone. /triage is the one human gate that grants autonomy (auto:build, optionally stacked with auto:merge); GitHub's own permission model makes applying that label a maintainer's signature, since an issue body is untrusted, prompt-injectable input. /dispatch then claims authorized records and hands them to the normal build pipeline.
