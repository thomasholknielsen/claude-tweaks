# Plugin structure and commands

Directory layout, the per-skill sub-file table, and the full command reference for the claude-tweaks plugin.

Extracted from [CLAUDE.md](../CLAUDE.md) so the always-loaded file stays lean — every dispatched subagent inherits `CLAUDE.md` in its system prompt, so bytes there are paid per agent, not per session. `CLAUDE.md`'s own `## Structure` section keeps the orientation summary and points here for the detail.

## Structure

```

plugin/skills/{name}/SKILL.md     → Skill definition (frontmatter + body)

plugin/bin/lib/transcript-judge/  → watermark.js (per-consumer evaluation-watermark read/write, byte-to-line conversion for delta-scoped re-judging — a second judge run against the same transcript evaluates only the delta since the last run, or skips the dispatch altogether when `isTranscriptUnchanged` reports no growth since the watermark (#701), namespaced per consumer so two consumers judging the same transcript never share state). Consumed by plugin/skills/_shared/transcript-judge.md and its consumers (plugin/skills/feedback/session-evaluation.md; plugin/skills/reflect/SKILL.md, #857)
plugin/bin/lib/declined-learning/ → store.js (one shared, flat degrade-open cache recording `{fingerprint, declinedAt, reason, source, subject?}` for findings/insights a human explicitly declined — `subject` (#1033) is optional human-legible text behind the fingerprint, absent on any entry recorded before it existed; `listDeclined` returns full entries including `subject`, alongside the pre-#1033 `listDeclinedFingerprints` — same injectable-fs conventions as transcript-judge/watermark.js, single file rather than per-consumer since every entry carries its own `source`). Consumed by plugin/skills/_shared/upstream-feedback-batch.md and plugin/skills/feedback/session-evaluation.md (`/feedback` Step 7 declines), plugin/skills/feedback/SKILL.md Step 4 (`lookupDecline` Prior-decline annotation, #1033), and plugin/skills/reflect/full-mode.md and reflect/SKILL.md (`/wrap-up` reflect insight resolution and transcript-judge dispatch, #1033) — #849

Plus option-description.js (#659): parses `AskUserQuestion` option `description` fields and flags a literal `?` — deliberation leaking into the option surface instead of stating the consequence, per docs/skill-authoring.md's Decisions bullet — exercised only by its own corpus-wide conformance test, never called at harness-health runtime
plugin/bin/lib/wrap-up/           → Three module families. (1) Deterministic git-fact readers for the wrap-up State block: reflog.js classifies `git reflog` history into report-worthy ops (rebase, reset, cherry-pick, revert, amend, merge, push), state.js reads branch/upstream/ahead-behind/pushed/linked-worktree facts, render.js renders the block. Consumed by plugin/bin/wrap-up-state.js so the report reads repository facts from git instead of reconstructing them from memory — the motivating failure this closes was a report claiming work had landed when it had only been committed locally. (2) The Phase 2 curation engine: registry.js is the machine half of SKILL.md's registry table (rows, gates, scopes, judges, dispositions — `tests/wrap-up-registry-pin.test.js` fails when the two drift), facts.js computes every fact-based gate from git and the filesystem, engine-plan.js builds the worklist and pre-resolves closed rows, engine-record.js validates one judgment payload per open row and appends its SCANNED + telemetry lines, engine-render.js renders the Phase 2 trace table and the Review Console's engine-fed sections behind a forbidden-vocabulary post-check. Consumed by plugin/bin/wrap-up-engine.js so row ordering, gate evaluation, and output formatting are program-owned rather than seven hand-maintained prose formats. (3) engine-verify.js — the Phase 4 closure-gate: nine deterministic checks (plans+ledger removal, design caches, run-dir archival, worktree removal, carrier commit, reference-repair scoping, acceptance labeling, memory updates, upstream feedback) replacing `execution-and-verification.md`'s old hand-run "Verify execution" checklist, read against `verify-expectations.json` (written by the Review Console) for the checks whose expected values live outside git/fs. Consumed by plugin/bin/wrap-up-engine.js's `verify` verb
plugin/bin/lib/residue/           → The wrap-up Outstanding-residue sweep: finding.js (shared finding shape + fingerprint id), scope.js (resolves the blast-radius base — merged branches, worktrees, head branch — with ran:false/reason when it can't), probes/{worktrees,branches,forge,suite,release,pipeline-runs,artifacts}.js (independent probes, each returning `{ran, reason, findings}`; the runner shape they take differs per probe — see plugin/bin/residue.js's own inline note; pipeline-runs sweeps `.claude-tweaks/pipelines/` directly for a run whose `run-state.json` reached `status: clean` without being archived under `archive/`; artifacts ages out QA evidence under `.claude-tweaks/artifacts/` on a 30-day newest-file rule, and surfaces legacy project-root `screenshots/`/`traces/` trees only when they match the pre-relocation plugin shape and `git ls-files` shows nothing tracked under them, always at `remedy: record` — never `auto`, since neither signal proves plugin ownership), render.js (the Outstanding table — a finding with no disposition renders the literal `NEEDS DISPOSITION`, never blank; an unrun probe renders `unknown` with its reason rather than silently reading as clean). Consumed by plugin/bin/residue.js
plugin/bin/lib/model-profiles/    → The work-profile system: profiles.js (the `Fast | Standard | Capable | Frontier` table + resolve(), merging policy overrides, run stance, CLI overrides, and session-failure avoidance in precedence order — table default, policy row, cliOverride, stance, model-ceiling, frontier gates, session-failure avoidance, with the last stage that changed the result naming `source`), policy-fragment.js (the nested `.claude-tweaks/policy.yml` model-config reader, deliberately separate from policy-schema.js's flat-only parser), session-failures.js (the session-scoped model-failure blacklist, #763: `os.tmpdir()`-keyed by `CLAUDE_CODE_SESSION_ID`, an mkdir-based lock around `recordFailure`'s read-modify-write, and `invalidateFailures` as its recovery path — #841). Consumed by plugin/bin/resolve-profile.js, the CLI wrapper dispatch sites resolve profiles through (its `record-failure`/`clear-failures` subcommands read/clear the blacklist); contract cited by `plugin/skills/_shared/subagent-output-contract.md` §Model Selection
plugin/bin/lib/reconcile/         → The `integration-model: pr-first` background convergence module (#405-#415): mirror-ff.js (fast-forwards a merged run's worktree branch), red-tip.js (inform-tier failing-CI detection on the integration branch's tip, #561), reap-merged.js (removes a merged run's worktree), release-merged.js (releases its issue claim on merged-PR or issue-closed evidence), archive-merged.js (archives its run dir), archive-branches.js (archives/deletes abandoned plugin-owned local branches + ages archive/* tags), prune-remote.js (deletes remote plugin-owned branches proven merged — MERGED PR + cherry-equivalence; the family's one pushed mutation), console-execute.js (executes an answered Review-Console PR — gh-CLI-only by design, no MCP fallback), classify.js + pr-state.js (shared PR-state classification: `resolvePrState` per branch, plus `resolvePrStatesBulk` — the chunked aliased-GraphQL screen resolving a whole branch set in ceil(N/50) all-or-nothing round trips, #1082). Both destructive branch checks read it screen-then-confirm: archive-branches and prune-remote screen the in-scope set in one bulk call and re-read per-branch only to confirm a destructive provisional verdict, differing deliberately on screen failure (prune-remote fails the whole check; archive-branches degrades to per-branch skips so its gh-independent archive-tag aging keeps running, #1083) and on the multi-PR tie-break (only prune-remote passes `preferOpen`, since its deletion is pushed and unrecoverable, #664). The #820 latency work adds five more: preflight.js (one cheap upfront GitHub-health check so a pass degrades once, fast, instead of every network-dependent check separately discovering the same outage via its own timeout), budget.js (an overall wall-clock ceiling for one pass, bounding the SUM across checks rather than any single check), cache.js (one local, gitignored best-effort cache file under the MAIN checkout backing both the short-TTL "skip the whole pass" gate and the per-claim content-addressed skip), gh-pool.js (a concurrency-capped async mapper for the family's per-item `gh` calls, where a per-item failure never aborts the batch), shared-fetch.js (the one `git fetch` a pass performs, shared by mirror and prune-remote, its shape scoped to which of the two was actually requested). index.js's `reconcile()` runs the checks (mirror → red-tip → console → release → archive → archive-branches → remote-prune → reap, reap last since it physically removes worktrees) from SessionStart and dispatch's own trigger points, no session continuity required — but SessionStart runs only mirror/red-tip/console inline and defers the other five to a detached `reconcile-background` child process, surfaced one session later (see docs/hooks.md's Background convergence bullet). Coverage lives in tests/bin-lib/reconcile/ plus tests/reconcile.test.js, tests/console-execute.test.js, and the other top-level tests/*.test.js files the npm test glob already picks up
plugin/bin/lib/issues/            → The work-record module family: record.js (recordPayload, facets, fingerprints, dependency parsing/queries), local-store.js (createRecord/readRecord/writeRecord, deriveSlug), grouping.js (groupByFileOverlap), capabilities-probe.js (native feature probes), claims.js (claim lock payloads + classification), claim-store.js (the one write-path implementation for the claims-registry blob store — tries a git compare-and-swap first via claims-git-cas.js, falling back to a contents-API PUT against `claims/issue-{n}.json` on `CLAIMS_BRANCH` when git-CAS fails for a transport reason or a secondary rate limit, #787; shared by plugin/bin/claim-targets.js and reconcile/release-merged.js's read paths — the write path for a release specifically goes through plugin/bin/lib/release-claim/release.js's writeTombstone instead, per that module's own header; also exports `tombstoneInFlightPr`, the #315 in-flight-PR check, moved here from the retired claim-engine.js), claims-git-cas.js (the git compare-and-swap core — fetch/show read, index-based commit + `push --force-with-lease` write, #787), materialize-format.js (materialize.md's shape gate, Surface/Design-intent/Ui-stack/Design-seed lift, pinned-header composition), backlog.js + ranking.js (the `/claude-tweaks:backlog` overview surface: `funnelBuckets`' mutually exclusive stage partition — including the `parents` bucket that keeps decomposition parents out of every actionable stage — plus `machineGrantOutlook` (phase-1 grant-gate outlook for overview's config-aware stage annotations), `refineWorklist`, `readyGrantedSubset`, and `rankNextToBuild`; this list guides to the largest modules rather than indexing the full directory), grant-gate.js/autonomy.js/trust.js (authorization), merge-lane-breaker.js (the global merge-lane circuit breaker, #311 — `merge-lane/` namespace on the `health-state` branch via `bin/lib/health-core/durable-state.js`'s extracted `createNamespacedState`; consumed by `grant-mode.md` Step 0.5/Step 4 and `refine-mode.md`'s `merge-lane-reset.md`), link.js (/specify Step 4 native linking — one aliased GraphQL databaseId batch, then per-edge sub_issues + dependencies/blocked_by POSTs each independently try/caught into {ok, failed}; Consumed by the record skills and by plugin/bin/link-records.js, plugin/bin/materialize.js, plugin/bin/claim-targets.js, plugin/bin/release-claim.js
```
