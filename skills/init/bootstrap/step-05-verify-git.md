# Step 5 — Verify Git (detailed procedure)

*Core Bootstrap step — order-dependent, so later steps may assume earlier ones completed; runs unconditionally and idempotently, acting only on missing state. Gated by `version-check.md` in this directory.*

The workflow system relies on git for change tracking (`/claude-tweaks:review` uses `git diff`, `/claude-tweaks:wrap-up` checks recent commits).

- Check that the current directory is a git repo (`git rev-parse --is-inside-work-tree`).
- If not, warn the user — the workflow will partially work but `/claude-tweaks:review` and `/claude-tweaks:wrap-up` will be degraded. Do not auto-run `git init` — the user may have an intentional non-git checkout. Worktree isolation (Phase 9's write step, below) is also unavailable here — there's no repo to isolate against, so Phase 9 falls back to writing directly, same as every phase did before Phase 9's own worktree-isolation change.
- **If it is a git repo, also check for a valid HEAD** (`git rev-parse --verify -q HEAD`). A repo with zero commits has no ref for a worktree to branch from — Phase 9's write step (and Step 6's deferred `worktree-always` write, when queued) needs one to exist. If HEAD doesn't resolve, create one now: `git commit --allow-empty -m "Initial commit (created by /claude-tweaks:init to enable worktree isolation)"`. Never commit the user's actual untracked files here — an empty commit gives git a valid ref without deciding on their behalf what belongs in history. Surface this as an informational notice, not a gated question — it's low-risk (trivially revertable, adds no content) and necessary for a step later in this same run: "This repo has no commits yet — created an empty initial commit so /init's own writes can be isolated in a worktree." Log the same in `auto` mode.
