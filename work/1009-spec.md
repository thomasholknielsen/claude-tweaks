# 1009: reconcile-threw fallback missing redTip key (bin/hooks.js)

Surface: backend

## Current State

`plugin/bin/hooks.js`'s `reconcile-threw` fallback (the object substituted for `reconcile()`'s
real return value when that async call throws — see the `reconcile` subcommand handler) is a
hand-maintained duplicate of `reconcile()`'s result shape. It currently reads:

```js
out = { mirror: null, worktrees: null, claims: null, runs: null, branches: null, remoteBranches: null, console: null, skipped: [{ check: 'all', reason: 'reconcile-threw' }] };
```

`plugin/bin/lib/reconcile/index.js`'s real result object (line 45) is:

```js
const result = { mirror: null, redTip: null, worktrees: null, claims: null, runs: null, branches: null, remoteBranches: null, console: null, skipped: [] };
```

The fallback is missing `redTip`. This is exactly the "hand-maintained duplicate silently
under-reports on omission" hazard `docs/reconcile-checks.md` (added by #551) now documents as its
own bullet in the "Adding a new check" procedure — but it's a live, pre-existing instance of that
hazard, not a hypothetical one. Found during #551's review; out of scope for that record since
`bin/hooks.js` is not in its diff (docs-only change).

Current impact is narrow: `bin/lib/hooks/session-start.js` only ever reads `result.redTip`
truthily (`if (result.redTip)`), and `undefined` is falsy exactly like `null`, so the inline
consumer degrades silently today. The `--json` output path (`bin/hooks.js`'s `reconcile`
subcommand) is the one place this actually differs: `JSON.stringify` on the fallback omits the
`redTip` key entirely rather than emitting `redTip: null`, which is a real shape drift for any
JSON consumer that expects the key to always be present (dispatch/tidy read other keys off this
same object today; a future consumer reading `redTip` off the throw path would silently get
`undefined` via `?.` or `!== null` checks, not the same signal a null value gives).

## Deliverables

1. Add `redTip: null` to the `reconcile-threw` fallback object literal in `plugin/bin/hooks.js`
   (the `reconcile` subcommand handler), matching `reconcile()`'s real result shape exactly.

## Acceptance Criteria

- The fallback object literal includes `redTip: null` alongside its existing keys.
- `npm test` passes.
- If a shape-asserting test exists for this fallback (check `tests/reconcile.test.js` and any
  `bin/hooks.js`-focused test file), it now asserts on the corrected shape; if none exists, one is
  not required by this record but may be added — this is deliberately not blocking (a small,
  well-understood fix).

## Gotchas

- This is a genuinely tiny fix (one key, one line) — don't gold-plate it into a broader refactor
  of the fallback mechanism.
