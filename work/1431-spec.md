# 1431: subagent-stop.js contract-violation events cross-contaminate across concurrent pipeline runs

Surface: backend

## Current State

During #1108's review, `events.jsonl` in that run's pipeline directory
(`.claude-tweaks/pipelines/2026-08-25T052702-record-1108/`) contained three
`"type":"contract-violation"` entries whose `firstLine` content
(`FROZEN_FORWARD_ROW`/"Phase 2 constants", "Line widths stay within the
file's ~98-col style", "Origin matches local HEAD") is unrelated to #1108's
own docs-only scope. `FROZEN_FORWARD_ROW` traces to a concurrent, unrelated
sibling run (`spec-1275-1274`).

Root cause: `plugin/bin/lib/hooks/subagent-stop.js`'s `run(ctx)` (line 43-51)
appends this event using the raw `ctx.runDir`, which `context.js`'s
`resolveRun` (line ~218-245) can set via a documented `attribution:
'fallback'` guess when the calling session has no confirmed run ownership.
`post-tool-use.js` was already hardened against the identical failure mode
for the sibling `commit` event type (line ~579-587) — scoped to
`ctx.ownedRun` (a session's confirmed identity, always populated by
`bin/hooks.js`'s `runHook`, line ~772-773) instead of `ctx.runDir` (possibly
a cross-session guess), passing `ownedRun.attribution` through to
`appendEvent`'s fourth argument so a guessed line is stamped
`attribution: 'fallback'` and stays filterable rather than silently trusted
— but `subagent-stop.js` never received that same hardening; it still
gates only on `if (!ctx.runDir) return {};` (line 44) and calls
`appendEvent(ctx.runDir, 'contract-violation', {...})` with no attribution
argument at all (line 50).

A spot-check of 5 other run directories found the same unrelated-firstLine
pattern in 1 of 5 non-empty `events.jsonl` files, confirming this recurs
rather than being a #1108-specific fluke. A grep of every `appendEvent(`
call site under `plugin/bin/lib/hooks/*.js` (excluding `context.js` itself,
where `appendEvent` is defined) additionally found several `ctx.runDir`-gated
calls in `pre-tool-use.js` (lines ~877, 881, 1137, 1157, 1163, 1174) that
were not part of #1108's original spot-check and have not yet been judged
against this same distinction.

## Deliverables

- [ ] Apply `post-tool-use.js`'s `ctx.ownedRun`-scoping + attribution-tagging
      pattern to `subagent-stop.js`'s `contract-violation` event append
- [ ] Audit the other `appendEvent` call sites in `bin/lib/hooks/` found
      during this pass (`pre-tool-use.js` lines ~877, 881, 1137, 1157, 1163,
      1174) for the same unhardened `ctx.runDir` (vs. `ctx.ownedRun`) usage,
      and harden each one that turns out to be an event-attribution write
      rather than a session-agnostic worktree-bookkeeping comparison

## Acceptance Criteria

1. A `SubagentStop` hook firing in a session with no confirmed run ownership
   (fallback-attributed `ctx.runDir`) either tags the appended event as
   fallback-attributed or does not append it to a run directory it does not
   own, matching `post-tool-use.js`'s existing `commit`-event hardening
2. Each `pre-tool-use.js` call site named in Deliverables is individually
   resolved — either hardened to `ctx.ownedRun` with attribution tagging, or
   left as `ctx.runDir` with a one-line comment recording why that call is a
   session-agnostic worktree-bookkeeping comparison rather than an
   event-attribution write (so a future audit doesn't re-flag it as an
   unreviewed gap)
3. `node --test tests/hooks-log-modules.test.js` continues to pass, extended
   with a case asserting that a fallback-attributed run either doesn't
   receive the `contract-violation` event or receives it tagged
   `attribution: 'fallback'`

## Technical Approach

In `subagent-stop.js`'s `run(ctx)`, replace the `if (!ctx.runDir) return {};`
guard and the bare `ctxLib.appendEvent(ctx.runDir, 'contract-violation', {...})`
call with the same shape `post-tool-use.js`'s commit-event handler already
uses:

```js
const ownedRun = ctx.ownedRun || {};
if (!ownedRun.dir) return {};
...
ctxLib.appendEvent(ownedRun.dir, 'contract-violation', { firstLine }, ownedRun.attribution);
```

No plumbing changes are needed elsewhere: `bin/hooks.js`'s `runHook` already
resolves and passes `ownedRun` into every hook module's `ctx` (line
~772-773), so this is a same-file, same-function edit.

For the audit deliverable, judge each `pre-tool-use.js` call site on
whether it's an event-attribution log write (harden it) or a check that
legitimately needs the session-agnostic "run this worktree is currently
assigned to" (`ctx.runDir`) rather than "a run this session owns"
(`ctx.ownedRun`) — the two are not interchangeable in every context, only
in the event-logging one this record is about. `close-run-state.js`'s
single `appendEvent(runDir, 'close-without-wrapup', {})` call (line ~60) is
a different call path (an explicit CLI `close-run` invocation already scoped
via an explicit `--run` flag or the newest-non-terminal fallback) and is out
of scope for this record.

### Key Files

- `plugin/bin/lib/hooks/subagent-stop.js` — swap the `ctx.runDir` gate and
  unattributed `appendEvent` call for `ctx.ownedRun`-scoped gate +
  attribution-tagged `appendEvent`, mirroring `post-tool-use.js`'s
  commit-event pattern
- `plugin/bin/lib/hooks/post-tool-use.js` — reference pattern only (lines
  ~579-587); no change expected
- `plugin/bin/lib/hooks/pre-tool-use.js` — audit target: `appendEvent(ctx.runDir, ...)`
  calls at lines ~877, 881, 1137, 1157, 1163, 1174, each individually judged
- `tests/hooks-log-modules.test.js` — existing `subagent-stop` coverage
  (lines ~76-146); extend with a fallback-attribution case

## Gotchas

- `post-tool-use.js`'s hardening pattern passes `ownedRun.attribution` as
  `appendEvent`'s fourth argument; `context.js`'s `appendEvent` (line ~481)
  only stamps an `attribution` field on the written event when that value is
  literally `'fallback'` — passing it unconditionally is safe and matches
  the existing call sites, no extra conditional needed at the call site.
- `subagent-stop.js`'s doc comment (lines 1-8) already documents SubagentStop
  as "best-effort by design" — the fix must stay a no-op-on-uncertainty
  change (drop or tag, never block), consistent with that stated posture.
- Not every `ctx.runDir` usage in `pre-tool-use.js` is a bug: several exist
  to compare against "the run this worktree is currently assigned to"
  (a session-agnostic fact), which is a different question from "does this
  session own a run to write to." Hardening indiscriminately would silently
  change worktree-bookkeeping behavior that isn't part of this record's
  scope — each site needs its own read, not a blanket find-and-replace.
