# 1108: Worktree-isolation Bash guard false-positives on benign heredoc/printf commands

Origin: reflect light from #663
Defer-reason: tangential

## Current State

During record-663's review+polish+wrap-up dispatch, the worktree-isolation
Bash guard twice refused benign, non-git commands with the generic "too
complex to verify that it stays inside the worktree" message: a heredoc
appending prose to decisions.md with no git operation at all, and a plain
`printf '%s\n' "$VAR"` command. Both were harmless single-command
reads/appends. This is a distinct trigger shape from the already-documented
"literal arg complete" false positive (see this project's own operator
memory) - the guard appears to pattern-match on syntactic complexity
(heredocs, certain punctuation, $VAR references) rather than actually
detecting a cross-worktree git operation, producing false positives on
ordinary shell idioms unrelated to git.

## Deliverables

- [ ] Reproduce the false-positive trigger on a heredoc and a printf/$VAR
      command with no git operation present
- [ ] Narrow the guard's complexity heuristic so it flags actual git/path
      operations rather than any heredoc or $VAR-containing command

## Acceptance Criteria

1. A heredoc appending plain text to a file, and a printf command
   interpolating an env var, both with no git invocation present, no longer
   trip the worktree-isolation guard inside a linked worktree session
