# 1317: backlog refine: no "ready but human-only" outcome — RECOMMEND_BUILD:false on a scored record strips ready and loops on re-add

Origin: /claude-tweaks:backlog refine run 2026-08-23 (standalone run dir 2026-08-23T161118-backlog-standalone), observed while auto-applying the flag-back lane under autonomy: unattended

Defer-reason: tangential

## Current State

`/claude-tweaks:backlog refine` has no "ready but human-only" outcome. `refine-mode.md` Step 3 maps every `RECOMMEND_BUILD: false` from `assess-agent-autonomy grant-check` to `flag back (needs scoring)`, and Step 5's Flag-back mechanics remove `ready` and post a comment whose `{reason}` is literally `needs scoring` for the recommended case. That is correct for an unscored record, but `grant-check` legitimately returns `false` on scored, spec-shaped records for content reasons — risk:high merge-authority work, a `Defer-reason: needs-human-decision` body, a deliverable that requires a human-present session (creating live cloud resources, running from the main checkout under `worktree-always`), or a record already resolved live. Observed on the 2026-08-23 refine run (standalone run dir `2026-08-23T161118-backlog-standalone`): #1294, #1311, #1302, #1301, #1296, #1227, #1307 were all flagged back; only #1307 actually lacked scoring.

Two consequences: (1) the stock `needs scoring` comment is false on a scored record, so the run had to substitute the grant-check RATIONALE as `{reason}` — an undocumented deviation; (2) re-adding `ready` re-enters the same grant-check → `false` → flag-back on the next refine, so a deliberately human-only record loops between `ready` and backlog forever and never stays dispatchable by a human. The skill conflates "not an autonomous-build candidate" with "not spec-shaped".
